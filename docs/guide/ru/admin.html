Сначала различите авторитетные настройки, отображение клиента и регистрацию при запуске.

02Определения датапака и оверлей настроек

Предметы и подсказки, группы питания, этапы, бонусы, качество, редкость и правила блоков поддерживают определения датапака; локальный оверлей мода находится в config/healthy_diet/datapack/.

Пример структуры пути

config/healthy_diet/datapack/data/<пространство имён>/healthy_diet/<тип>/<файл>.json

Например, quality_levels/ хранит определения качества, blocks/ — правила правого клика; другие типы ищите по фактическому пути источника в редакторе игры.

Оверлей, сохранённый редактором, загружается вместе с существующими датапаками мира. Перед изменением проверьте источник целевой записи; оверлей не заработает от копирования данных в старый config/healthy_diet/items/.

Поиск настройки предмета

Сначала определите пространство имён и ID предмета, затем найдите data/<пространство имён>/healthy_diet/items/<путь предмета>.json; для подсказок используется healthy_diet/tooltips/. Оверлей HD и запись другого датапака могут существовать одновременно: после удаления оверлея ниже может остаться определение датапака, поэтому полное отключение предмета не гарантировано.

Источник: загрузчик pack ConfigManager, PackJsonLoader, запрос источника оверлея.

03/hdreload и другие команды

/hdreload требует OP4, перечитывает только перезагружаемые настройки Healthy Diet и дисковый оверлей, затем повторно рассылает авторитетное содержимое игрокам в сети; это не полный /reload Minecraft. После ручного добавления, изменения или удаления файлов оверлея проверяйте результат по типам.

Игроки и предметы/headiet открывает панель питания; /hdui управляет предметом в руке и входами редактирования, /hdui stage — этапами питания.
Проверка и справка/hdhelp показывает синтаксис команд; /hdtemperature выводит разбивку температуры в текущей позиции; /hdtrust управляет списком доверия.

Административные команды открыты не всем; права зависят от условий регистрации каждой команды. /hdreload требует уровень прав 4. /hdconfig — локальная команда клиента, для её выполнения нужен OP4; это не команда консоли выделенного сервера. Игроки без OP могут войти в локальные настройки оформления через другие экраны; подробнее в схемах интерфейса настроек.

Как проверить после изменения

Сохраните или обновите оверлей HD, выполните /hdreload, проверьте ответ команды и счётчики блоков «загружено/вариант/отброшено», затем проверьте реальным предметом или блоком. Некоторые сохранения редактора уже вызывают перезагрузку мода; для датапаков мира или ресурсов других модов используйте их собственные процедуры, не считайте /hdreload ванильным /reload.

Источник: HDReloadCommand, HDUICommand, HDClientCommands.

04Что не обновляется одной перезагрузкой

  • 1Регистрация новых ID предметов: определения действуют при запуске; перезагрузка только пересчитывает план ожидания и не создаёт новый ID времени выполнения.
  • 2Локальные файлы клиента: например display.json, локальные градиенты, туман, не перечитываются принудительно серверным /hdreload.
  • 3Лимит стака: изменение свойства уровня предмета требует перезапуска; разные варианты NBT не могут иметь разные лимиты стака.

При добавлении зарегистрированных предметов качества на мультисервере клиент должен до входа получить одинаковый список регистрации и ресурсы, затем перезапуститься по процедуре регистрации. Не считайте «сервер перезагружен» равным «клиент уже имеет новый ID».

Три шага определения способа обновления: изменение перезагружаемых предметов, подсказок или данных питания → проверьте ответ и рассылку /hdreload. Изменение локального отображения/тумана игрока → клиент перечитывает локально. Добавление/удаление ID в quality_registry/, изменение лимита стака → перезапуск по требованиям регистрации при запуске или свойства предмета. Рассылка первого типа не означает завершение двух других.
Источник: QualityRegistryEntry, ItemConfig.stackSize, HDReloadCommand, ConfigManager.

Источник: условия прав классов регистрации команд; фактически ориентируйтесь на /hdhelp и установленные файлы.

06Необязательные интеграции и перезапуск

Необязательный модНазначение
JadeСрок годности для поддерживаемых выпавших продуктов.
Legendary Survival OverhaulИсточники данных об окружающей и ощущаемой температуре.
Ecliptic SeasonsИнтеграция сезонов, климата, температуры и сохранности.
Refurbished FurnitureСохранность в холодильнике/морозильнике; для NeoForge также нужен framework.

Это необязательные интеграции по функциям, а не обязательное условие базовой игры; проверьте доступность стороннего мода для вашей версии игры.

Когда нужен перезапуск: зарегистрированные при запуске предметы качества требуют одинаковых определений на обеих сторонах и применения при запуске; изменения содержимого запуска не применяются только синхронизацией после входа или /hdreload. Способ обновления локальных файлов отображения клиента также отличается от серверных игровых настроек.
Источник: QualityRegistryEntry, ConfigManager, проверки готовности модулей интеграции.
