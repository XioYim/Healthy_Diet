01 / NUTRITION

营养值，其实就三件事：吃什么、涨多少、什么时候触发。

别急着背数字。先把进度条和阶段看懂，剩下的规则就顺下来了。下面所有界面和数字都是示意，真正生效的永远是你所在服务器的配置。

0–100 可以带小数 阶段按整数判定 服务器说了算
先打个招呼：这篇是“看懂机制”，不是“背默认值”。你服务器的营养组、阶段、衰减率、命令和效果可能完全不一样；图里的数字只是用来讲清楚变化过程。

01一分钟看懂

把每个营养组想成一根独立的水槽：左边是 0，右边是 100。吃一口，就是往某几根水槽里加水；饿肚子，水槽也会慢慢漏水。

所以“吃苹果”不是只加一个数，而是可能同时推动水果和糖分两根条。不同食物推动的组不一样，这就是饮食结构的来源。

02涨与掉

吃一口，先算这一口加多少；饿肚子，再按衰减率慢慢掉。

进食增加的大致关系是：食物基础值 × 该组获取倍率，有终身厌食时还会再乘一个衰减系数。算完以后，最终值会被夹在 0–100。管理员指令、自然衰减和初始值不走“获取倍率”这个入口。

  • 1范围是 0–100。营养值可以带小数，但无论怎么加、怎么减，最后都不会冲出这个范围。
  • 2阶段判定看整数。系统会把当前值四舍五入后再找阶段，所以 59.6 会按 60 算。
  • 3死亡不会清空。重生时营养数据会跟着复制，不把死亡当成重新开始。
别拿示例当默认：衰减率、初始值和获取倍率都能被服务器改。想知道自己世界里的实际值，进游戏看 /headiet 面板或问服主。

03阶段

阶段就是给进度条贴标签：这一段叫“缺乏”，那一段叫“均衡”，再往右叫“过量”。标签只是名字，真正有用的是每段能挂什么。

阶段边界用整数划分，编辑器会检查相邻阶段，避免出现“小数刚好落在两个阶段中间”的空档。判定时先四舍五入，再找区间。

低 0–29
中 30–69
高 70–100
按整数判定：60 当前示例阶段：中段
阶段名称和 0–29 / 30–69 / 70–100 只是示例；你的服务器可能分更多段，也可能用完全不同的边界。

每个阶段能配什么

名称和描述 告诉玩家现在处于什么状态，以及这个状态要注意什么。描述会出现在营养面板的悬浮提示里。
点击命令 玩家在营养界面点击这一阶段时执行。命令以管理员权限运行，输出不刷屏。
自动加成预览 把这一阶段配置的属性和效果自动列进提示里；不想重复显示时可以关掉这个预览。
点击有冷却：同一玩家的阶段命令点击间隔是 1.5 秒，服务端也会再校验一次。命令内容由服主决定；陌生服务器上别乱点看不懂的阶段。

04加成和联动

阶段里可以挂两样东西：属性，或者药水效果。多个组同时满足条件，就是联动加成。

属性加成 比如最大生命、移动速度。默认大约每 5 秒评估一次；服务器可以调整。
药水效果 比如生命恢复、抗性提升。默认大约每 10 秒刷新；效果时长最好长于 10 秒，避免断档。
联动加成 把多个组的区间写进同一份条件，全部满足才给；不是“任意一个满足”。

联动条件不是“或”。任何一个组掉出区间，这个组合就不成立。
离开阶段会怎样：加成不再维持，由刷新周期更新。属性会回收，药水效果则按自己的剩余时长自然结束；所以效果时长要和刷新节奏配合。

05条件规则

普通营养值是“吃了就加”；条件规则是“先看条件，再决定这一口怎么算”。

它可以同时检查多个营养组，全部满足后，再对任意组做加减、执行命令，或者两件事一起做。条件组和目标组可以不是同一个组。

吃下食物先结算普通营养值
→
检查条件多个区间必须全部满足
→
执行结果营养变化 / 命令
→
夹到 0–100不会冲出范围
条件规则在普通营养结算之后判断，所以同一份食物对同一个组既写普通值、又写条件变化时，两段会先后生效。

一条条件规则 · 示意

触发条件 肉类 0–86 AND 水果 30–100
营养变化 肉类 +20 糖分 -5
可选 执行命令 显示提示 获取倍率

两个常见用法

把好东西限制在安全线内

条件：肉类在 0–86。目标：肉类 +20。

你现在 80，吃下去最多到 86 就停；你已经 90，条件不成立，这一口不增加。

把危险值拉回来

条件：肉类在 86–100。目标：肉类 -30。

你现在 95，吃下去会降到 86 附近就停，不会一口气降到缺乏区。

一个组别重复叠加：如果同一份食物对同一个组既配了普通营养值，又配了针对该组的条件变化，两段会先后生效。通常只选其中一种表达方式，别让它们互相打架。

06编辑器和变体

NBT 变体：同名物品，两套配置

同一个物品可以按 NBT 分成多个变体。每个变体保存自己的一份配置；玩家吃下时命中哪个变体，就用哪一份。比如同一瓶药水，可以给不同 NBT 配不同的营养。

变体 A 治疗药水
水果 +8
糖分 +4
变体 B 迅捷药水
蛋白质 +6
蔬菜 +3
变体数值只是示意。每个变体是独立配置，不是自动继承通用条。
堆叠上限是物品级的：同一物品的不同变体不能各设一个堆叠数。口渴值等按物品计算的配置也按同样思路处理。

常用入口

  • /hdui create：创建营养组、品质、品级或注册物品；组 ID 创建后不能改。
  • /hdui stage：打开阶段配置。
  • /hdui groups [玩家]：打开自己或指定玩家的营养面板。
  • /hdui registry：物品注册管理。
  • /hdui tooltip：手持物品的 Tooltip 编辑入口。

营养组定义现在由数据包承载；在编辑器里创建或修改会写入配置覆盖层。旧的 /hdgroups 已经删除。

07管理与命令

普通玩家看自己的面板就够了；改别人的数值、暂停组，需要相应权限。

命令用途
/headiet打开自己的营养面板。
/headiet add <玩家> <组> <数值>增加指定玩家的某组营养值。
/headiet subtract <玩家> <组> <数值>减少指定玩家的某组营养值。
/headiet set <玩家> <组> <数值>把某组设为指定值，支持小数。
/hdui groups [玩家]打开营养管理面板，可改值或暂停组。
暂停组：暂停后这个组既不随进食增加，也不自然衰减，适合剧情、新手保护或临时活动。恢复后按正常规则继续。
