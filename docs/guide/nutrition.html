常见默认配置包含六组：乳制品、水果、谷物、蛋白质、糖分、蔬菜。服务器可增删、改名或调整顺序。

01机制概览

每个营养组是一条独立的 0–100 数值轴。食物可同时影响多个组；饱食度下降时，各组按配置的衰减率减少。

同一份食物对不同组的贡献可以不同。例如苹果同时增加水果和糖分；食物之间的差异构成饮食结构。

数值体系：饱食度与营养值相互独立；饱食度用于饥饿与进食，营养值用于长期饮食结构。

02增加与衰减

进食增加与饱食度衰减是两条独立结算路径。

进食增加量约为：食物基础值 × 该组获取倍率；存在终身厌食时再乘以衰减系数。结算后按 0–100 夹取。管理员指令、自然衰减和初始值不经过获取倍率。

03阶段

阶段是营养值区间及其关联行为；阶段标题、描述和点击指令在阶段页编辑，跨组的持续效果与属性加成在独立效果页按区间条件配置。

阶段边界使用整数。编辑器会校验相邻区间，避免数值落在阶段之间的空档；判定时先四舍五入，再匹配区间。

低 0–29
中 30–69
高 70–100
按整数判定：60 当前示例阶段：中段
阶段名称与 0–29 / 30–69 / 70–100 仅为示例；服务器可配置更多阶段或不同边界。

阶段可配置项

名称与描述 标识阶段并说明当前状态；描述显示在营养面板的悬浮提示中。
点击命令 玩家点击阶段时执行；以管理员权限运行，输出被抑制。
自动加成预览 将阶段配置的属性与效果自动加入提示；可关闭以避免重复显示。
点击冷却：阶段命令的同一玩家点击间隔为 1.5 秒，服务端会再次校验。命令由服主配置；请勿点击来源不明的阶段命令。

04加成与联动

独立效果页可为一个或多个营养组的区间组合配置持续属性修饰器和药水效果；全部条件满足时触发联动加成。它不是食物吃下后的一次性药水效果编辑页。

属性加成 例如最大生命、移动速度；默认约每 5 秒评估一次，服务器可调整。
药水效果 例如生命恢复、抗性提升；默认约每 10 秒刷新。默认节奏下，效果时长应长于 10 秒以避免断档。

05条件规则

普通营养结算在进食时直接执行；条件规则在普通结算之后，根据营养区间决定额外变化或命令。

条件规则可同时检查多个营养组，全部满足后对任意组执行加减、运行命令，或同时执行两者。条件组与目标组可以不同。

条件规则在普通营养结算之后执行；同一食物对同一组同时配置普通值与条件变化时，两段会依次结算。

一条条件规则 · 示意

触发条件 肉类 0–86 AND 水果 30–100
营养变化 肉类 +20 糖分 -5
可选 执行命令 显示提示 获取倍率

两种常见配置

限制上限

条件：肉类在 0–86。目标：肉类 +20。

当前 80 时进食，最多到 86；当前 90 时条件不成立，不增加。

回落修正

条件：肉类在 86–100。目标：肉类 -30。

当前 95 时进食，降至 86 附近即停止，不会继续落入低值区。

同一组的重复结算：若同一食物对同一组同时配置普通营养值与条件变化，两段会依次执行。通常只保留一种表达方式，避免重复结算。

手持物品输入 /hdui，打开该物品的配置入口。

编辑器集成营养、厌倦、口渴、饱食度、堆叠、品质、保质期、效果、指令、条件与清除效果。下图为布局示意，并非实际截图。

物品编辑器 · 示意手持物品 /hdui

另一个入口：/hdui create 的营养值 Tab

/hdui create 要求 OP4，创建/修改的是营养组定义，并非修改某位玩家当前数值。品质和品级位于同一编辑器的另外两个 Tab；品质图、品级图可直接跳转。

界面依据：HdCreateScreen.buildGroupForm/buildHeaderButtons/groupErrors；注册新物品另见 注册管理器。

NBT 变体：同名物品的独立配置

同一物品可按 NBT 划分为多个变体，每个变体保存独立配置；进食时使用命中变体的配置。例如同一药水的不同 NBT 可配置不同营养。

变体 A 治疗药水
水果 +8
糖分 +4
变体 B 迅捷药水
蛋白质 +6
蔬菜 +3
变体数值为示意。每个变体保存独立配置，不自动继承通用条。
堆叠上限为物品级属性：同一物品的不同变体不能设置不同堆叠数。口渴值等物品级配置同理。

常用入口

  • /hdui create (OP4)：创建/修改营养组、品质、品级定义；组 ID 创建后不可随意改，不注册独立物品。
  • /hdui stage (OP4)：打开阶段/指令/描述编辑，绿色“效果”通往独立加成页。
  • /hdui groups [玩家] (OP4)：执行者打开自己或指定玩家的数值管理屏，不是普通营养面板，也不创建组定义。
  • /hdui registry (OP4)：打开注册管理器查看、刷新和删除注册项；新物品 ID 按启动流程生效。
  • /hdui tooltip (OP4)：手持物品的 Tooltip 编辑入口；详见Tooltip 编辑。

营养组定义由数据包承载；编辑器中的创建或修改会写入配置覆盖层。旧 /hdgroups 已删除。

07管理与命令

普通玩家可查看自身面板；修改其他玩家数值或暂停营养组需要相应权限。

命令权限 / 用途与对象
/headiet 或 /headiet open玩家本人，无 OP 要求：把营养面板发给自己。
/headiet open <玩家>OP2：把营养面板发给指定玩家，不是执行者查看该玩家的面板。
/headiet add <玩家> <组> <数值>OP4：增加目标玩家对应组数值；输入 0–100，可带小数。
/headiet subtract <玩家> <组> <数值>OP4：减少目标玩家对应组数值；输入 0–100，可带小数。
/headiet set <玩家> <组> <数值>OP4：把目标玩家对应组设为指定值；输入 0–100，可带小数。
/hdui groups [玩家]OP4：执行者打开自己或指定玩家的营养管理屏，可调数值或暂停组；并非组定义编辑。
暂停组：暂停期间该组不随进食增加，也不自然衰减；适用于剧情、新手保护或限时活动。恢复后按正常规则继续。

08要点回顾

  1. 数值范围为 0–100。小数保留，阶段判定时四舍五入。
  2. 营养值随饱食度消耗按衰减率下降。饱和度不参与；死亡不清空。
  3. 阶段控制持续状态，条件规则控制单次进食结算。实际组、阈值与效果以服务器配置为准。
