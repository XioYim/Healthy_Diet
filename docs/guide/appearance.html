01颜色方案与纯色板

渐变方案在 colors/color_schemes.json 中以 ID 引用；纯色板在 colors/solid_colors.json 中定义可选颜色。

例如营养组的配色可以引用一个渐变方案；品质和提示行也可以配置方案或直接使用纯色。颜色表提供的是颜色来源，不决定某条提示是否显示。

02静态渐变与动态样式

静态文字可按字符分配渐变色，不随时间变化；需要动态效果时才启用对应开关。
动态当前支持 gradient、breathing、wave、pulse 等样式；速度、步数与部分特有参数分别配置。

波动和脉冲还提供各自的步距或延迟；颜色顺序反转与动画方向反转也是两项独立设置。提示行可由多个文本段组成，每段拥有自己的配色与动画参数。

源码依据：TooltipLineConfig 的 dynamic、nameStyle、segments、colorReverse、dynamicReverse。

03颜色应用在何处

  • 1物品名与 Tooltip 附加行：可配置文字、渐变、分段、动态样式及显示条件；名称行与附加行的限制不同。
  • 2品质与品级：品质可有覆盖层、分段品质文字；品级影响稀有度标签及相关物品名颜色。
  • 3厌倦信息：使用 fatigue/fatigue_gradient.json 管理厌倦相关的提示色彩。
  • 4保质期状态：使用 shelf_life/schemes/ 中的保质期显示方案，区别于通用渐变色板。
源码依据：QualityLevelConfig、TooltipLineConfig、ConfigManager 的保质期方案与厌倦渐变路径。

04服务端规则与客户端显示

服主可以维护规则性内容并同步给在线玩家，例如食物提示布局、品质定义与保质期显示方案。客户端本地的显示设置和部分本地配色文件不会因为服务端执行 /hdreload 就自动远程重读。

因此，修改外观前先区分配置文件是在服务端下发，还是需要每个客户端自行安装、重载或重进世界。对于注册品质物品的自定义贴图，客户端还须拥有相应资源。

路径迁移：旧版 rarity_and_colors/ 与 shelf_env/ 目录不是现行编辑路径；请看实际安装目录的 colors/、fatigue/ 和 shelf_life/。
提示行怎样显示？先看普通、S 与 D 模式，再决定给某行应用何种配色。
