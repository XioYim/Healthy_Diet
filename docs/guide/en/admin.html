02Datapack definitions and local overrides

Items, tooltips, nutrition groups/stages/bonuses, quality, rarity and block rules use datapacks. The HD-local override root is config/healthy_diet/datapack/data/<namespace>/healthy_diet/<type>/<file>.json. For an item, inspect data/<namespace>/healthy_diet/items/<itemPath>.json; tooltips use tooltips/, quality uses quality_levels/, blocks use blocks/. Confirm which pack supplies an entry before editing; deleting a top-layer override can expose a lower-priority definition instead of disabling the item.

03What /hdreload does

/hdreload (OP4) rereads Healthy Diet reloadable configuration and its disk override layer, then resends authoritative content to online players. It is not Minecraft’s full /reload. Some editor saves already trigger a mod reload. After modifying an override, inspect command feedback (including loaded/discarded block-variant counts) and test a real item or block. World datapacks and other mods follow their own reload procedure.

/hdconfig is a client-local command requiring OP4 to invoke; it is not registered on a dedicated-server console. Non-OP players may still reach their local appearance settings through other screens.

04Changes requiring another procedure

  1. New registered item IDs: registry definitions take effect at startup. Distribute identical definitions and resources to client/server and restart.
  2. Local client files: display.json, local gradients and fog settings are not forcibly reread by a server /hdreload.
  3. Stack limits: changing an item-level stack-size property requires restart; different NBT variants cannot have different stack sizes.
Successful synchronization of one server rule does not mean clients have received a newly registered item ID or local resource.
