01Nutrition groups and panel

Each group is an independent 0–100 value. A food can affect multiple groups (for example, an apple can supply fruit and sugar). Consumption affects group values; hunger-point consumption causes configurable decay. The common bundled groups are dairy, fruit, grains, protein, sugar and vegetables, but servers can add, remove, rename and reorder groups.

03Stages and their editor

A stage is an integer nutrition interval with optional title, hover description and click commands. Adjacent intervals must not overlap or leave gaps; the server rounds the current value before matching. /hdui stage (OP4) offers separate Stage, Command and Description tabs for enabled groups. A green Effects button opens a separate bonus page, not a fourth tab.

Those three named ranges are illustrative, not fixed defaults. Clicking a configured stage command runs it with administrator permission and suppressed output; a player may click at most once every 1.5 seconds and the server rechecks. Do not click untrusted stage commands.

04Ongoing bonuses and cross-group conditions

The separate Effects page can attach attribute modifiers and recurring potions to one or more nutrient intervals. All group conditions in a combined bonus must match. Attributes are recalculated about every five seconds by default; effects are refreshed about every ten seconds, so effect durations should exceed that cadence to avoid gaps. Exiting an interval removes attribute modifiers at the next refresh; potion effects expire over their remaining duration. This differs from one-shot food effects.

On the Effects screen, clicking a stage fills its bounds; manually typed bounds require selecting Custom before they take effect. Shift-click selects or deselects additional stages. 05Per-meal conditional rules

After ordinary nutrition from eating is settled, each conditional rule checks its required group ranges. If all match, it can modify any target group, run commands, show a result tip, or combine those actions. Condition groups and target groups need not be the same. Changes are clamped to 0–100. If the same food has both a normal value and a conditional change for a group, both paths run in sequence, so avoid unintentional double counting.

Example cap: condition protein 0–86, target protein +20. At 80 it rises at most to 86; at 90 the rule does not match. A correction rule can target protein −30 when current protein is 86–100; it stops around the lower condition boundary rather than decreasing indefinitely.

06Item editor, groups and variants

Hold an item and use /hdui (OP4) for nutrition, food fatigue, thirst, hunger, stack limit, quality binding, shelf life, potion effects, commands, conditional rules and effect removal. /hdui create (OP4) manages group definitions, quality and rarity; it does not edit a player’s current value or register a new item. Group definitions can include ID, localized display name, icon, decay rate, initial value, gain multiplier, player tag, required mod ID, order, enable switch and four nutrient tip colors.

One item can define distinct NBT variants, such as two potion types with different nutrition; matching variants do not automatically inherit the generic entry. Stack size and some thirst fields are item-level, not per-variant. /hdui groups [player] opens a value-management screen; /hdui registry manages startup item registration; /hdui tooltip opens item tooltip editing. The old /hdgroups command has been removed.

08Takeaways

  1. Values stay within 0–100, retain decimals and round for stage checks.
  2. Hunger consumption drives natural decay; saturation does not. Death does not erase nutrition.
  3. Stages and recurring bonuses track ongoing state; per-food conditional rules settle during eating. Server files decide the real groups, thresholds and effects.
