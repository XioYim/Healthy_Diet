06 / APPEARANCE

Gradients and display styling

A scheme supplies colors; a style controls animation. Item names, quality, rarity, fatigue and shelf-life status have separate bindings.

01Schemes and solid palette

colors/color_schemes.json defines named gradient schemes; colors/solid_colors.json supplies selectable solid colors. Nutrient groups, quality definitions and tooltip lines may reference schemes or colors. A scheme supplies colors; it does not decide whether a line appears.

02Static gradients and animation

A static gradient assigns colors per character. Optional styles include gradient, breathing, wave and pulse. speed sets a cycle in milliseconds and steps samples the palette; waveStep and pulseDelay affect only their respective styles. Reversing color order and reversing animation direction are independent. With segmented text, each segment has its own colors and animation; top-level text parameters do not override segments.

03Where colors appear

  1. Item names and extra tooltip lines: configure text, gradient, segments, animation and visibility. Names and extra lines obey different restrictions.
  2. Quality labels / overlay and rarity labels: quality references its own definition; rarity can be overridden per item or NBT variant.
  3. Fatigue: fatigue/fatigue_gradient.json controls its tooltip colors.
  4. Shelf-life status: shelf_life/schemes/ is separate from the general gradient palette.
Copy generic name styling: /hdset tooltip <sourceItemId> hand|<targetItemId> (OP2) copies the source item’s generic first line scheme and animation fields to the main-hand target or explicit item ID. It does not copy text, stars, other lines or variants; segmented first lines are rejected. Edit segments in the tooltip editor.

04Server rules and local client display

Server-defined tooltip layouts, quality definitions and shelf-life schemes can be reloaded and synchronized to connected players. Client-only display settings and some local palettes are not forcibly reread when the server runs /hdreload. Check whether an appearance file is sent from the server or must be installed/reloaded locally. Custom registered-item textures require client resources too.

Do not follow old rarity_and_colors/ or shelf_env/ paths; inspect the installed colors/, fatigue/ and shelf_life/ directories.
