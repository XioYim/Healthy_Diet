營養值：數值、階段與條件規則。

本頁按結算順序說明營養組、衰減、階段、加成與條件規則。介面和數字均為示意，實際規則由伺服器設定決定。

常見預設設定包含六組：乳製品、水果、穀物、蛋白質、糖分、蔬菜。伺服器可增刪、改名或調整順序。

01機制概覽

每個營養組是一條獨立的 0–100 數值軸。食物可同時影響多個組；飽食度下降時，各組按設定的衰減率減少。

同一份食物對不同組的貢獻可以不同。例如蘋果同時增加水果和糖分；食物之間的差異構成飲食結構。

蘋 蘋果 範例食物
→
水果 +26
糖分 +12
範例：單份食物可影響多個組。進度條為結算後的示意值，不代表伺服器預設設定。

營養面板示意

按 H 開啟營養面板。組名、配色和階段範圍取自 Forge 主線內置 JSON；懸停或鍵盤聚焦每個階段，檢視其實際設定的加成預覽。預設階段沒有手寫名稱或描述，因此提示僅顯示區間、設定的加成與必要的點擊指令提示。

營養狀態 · 設定示意按 H 開啟
HTML 模擬介面，不是遊戲截圖。六個色塊不代替物品圖示；展示數值為範例玩家狀態，並非預設初始值。將滑鼠移到階段分區或使用 Tab 聚焦，檢視該段的實際預設加成；懸停「檢查完畢」可檢視這組範例值當前激活的加成。這裡不會實際執行遊戲指令。
設定來源：nutrition_groups.json 與預設資料包中的 nutrition_stages/*.json、nutrition_bonuses/*.json；配色來自 color_schemes.json。例如預設蔬菜組的 initialValue 為 42、decayRate 為 6；圖中 55% 只為展示 46–60 區間的加成。加成懸浮依據 HealthyDietScreen 與 BonusTooltipUtil，不是把任意描述寫進預設設定。
數值體系：飽食度與營養值相互獨立；飽食度用於飢餓與進食，營養值用於長期飲食結構。

02增加與衰減

進食增加與飽食度衰減是兩條獨立結算路徑。

進食增加量約為：食物基礎值 × 該組取得倍率；存在終身厭食時再乘以衰減係數。結算後按 0–100 夾取。管理員指令、自然衰減和初始值不經過取得倍率。

  • 2階段判定使用整數。當前值四捨五入後匹配階段，例如 59.6 按 60 處理。

範例與設定：衰減率、初始值和取得倍率均可由伺服器調整。實際數值以 /headiet 面板和伺服器設定為準。

03階段

階段是營養值區間及其關聯行為；階段標題、描述和點擊指令在階段頁編輯，跨組的持續效果與屬性加成在獨立效果頁按區間條件設定。

階段邊界使用整數。編輯器會校驗相鄰區間，避免數值落在階段之間的空檔；判定時先四捨五入，再匹配區間。

低 0–29
中 30–69
高 70–100
按整數判定：60 當前範例階段：中段
階段名稱與 0–29 / 30–69 / 70–100 僅為範例；伺服器可設定更多階段或不同邊界。

階段可設定項

名稱與描述 標識階段並說明當前狀態；描述顯示在營養面板的懸浮提示中。
點擊指令 玩家點擊階段時執行；以管理員權限執行，輸出被抑制。
自動加成預覽 將階段設定的屬性與效果自動加入提示；可關閉以避免重複顯示。
點擊冷卻：階段指令的同一玩家點擊間隔為 1.5 秒，伺服器端會再次校驗。指令由服主設定；請勿點擊來源不明的階段指令。

04加成與連動

獨立效果頁可為一個或多個營養組的區間組合設定持續屬性修飾器和藥水效果；全部條件滿足時觸發連動加成。它不是食物吃下後的一次性藥水效果編輯頁。

屬性加成 例如最大生命、移動速度；預設約每 5 秒評估一次，伺服器可調整。
藥水效果 例如生命恢復、抗性提升；預設約每 10 秒重新整理。預設節奏下，效果時長應長於 10 秒以避免斷檔。

離開階段後：加成不再維持，由重新整理周期更新。屬性修飾器會被回收；藥水效果按剩餘時長結束，因此時長需與重新整理節奏匹配。

獨立效果與屬性加成頁

從 階段頁的綠色「效果」入口進入；僅展示啟用組。點擊某組進度條的階段可填起止，手工輸入後需點「自選」才提交範圍。Shift 點擊可追加/取消選中階段；同時選取多個組時，對每個選中區間組合分別儲存到 nutrition_bonuses，不能將這些條件理解為一張單組階段表。

介面依據：EffectManageScreen.buildGroupRangeControls/buildBottomButtons/saveEffectRows 與當前 zh_cn 標籤。物品單次食用效果另見 食用藥水效果。

05條件規則

普通營養結算在進食時直接執行；條件規則在普通結算之後，根據營養區間決定額外變化或指令。

條件規則可同時檢查多個營養組，全部滿足後對任意組執行加減、執行指令，或同時執行兩者。條件組與目標組可以不同。

吃下食物先結算普通營養值
→
檢查條件多個區間必須全部滿足
→
執行結果營養變化 / 指令
→
夾到 0–100按邊界夾取
條件規則在普通營養結算之後執行；同一食物對同一組同時設定普通值與條件變化時，兩段會依次結算。

一條條件規則 · 示意

觸發條件 肉類 0–86 AND 水果 30–100
營養變化 肉類 +20 糖分 -5
可選 執行指令 顯示提示 取得倍率

兩種常見設定

限制上限

條件：肉類在 0–86。目標：肉類 +20。

當前 80 時進食，最多到 86；當前 90 時條件不成立，不增加。

回落修正

條件：肉類在 86–100。目標：肉類 -30。

當前 95 時進食，降至 86 附近即停止，不會繼續落入低值區。

同一組的重複結算：若同一食物對同一組同時設定普通營養值與條件變化，兩段會依次執行。通常只保留一種表達方式，避免重複結算。

06編輯器與變體

手持物品輸入 /hdui，開啟該物品的設定入口。

編輯器集成營養、厭倦、口渴、飽食度、堆疊、品質、保存期限、效果、指令、條件與清除效果。下圖為布局示意，並非實際截圖。

物品編輯器 · 示意手持物品 /hdui

另一個入口：/hdui create 的營養值 Tab

/hdui create 要求 OP4，建立/修改的是營養組定義，並非修改某位玩家當前數值。品質和品級位於同一編輯器的另外兩個 Tab；品質圖、品級圖可直接跳轉。

介面依據：HdCreateScreen.buildGroupForm/buildHeaderButtons/groupErrors；註冊新物品另見 註冊管理器。

NBT 變體：同名物品的獨立設定

同一物品可按 NBT 劃分為多個變體，每個變體儲存獨立設定；進食時使用命中變體的設定。例如同一藥水的不同 NBT 可設定不同營養。

變體 A 治療藥水
水果 +8
糖分 +4
變體 B 迅捷藥水
蛋白質 +6
蔬菜 +3
變體數值為示意。每個變體儲存獨立設定，不自動繼承通用條。
堆疊上限為物品級屬性：同一物品的不同變體不能設定不同堆疊數。口渴值等物品級設定同理。

常用入口

  • /hdui create (OP4)：建立/修改營養組、品質、品級定義；組 ID 建立後不可隨意改，不註冊獨立物品。
  • /hdui stage (OP4)：開啟階段/指令/描述編輯，綠色「效果」通往獨立加成頁。
  • /hdui groups [玩家] (OP4)：執行者開啟自己或指定玩家的數值管理屏，不是普通營養面板，也不建立組定義。
  • /hdui registry (OP4)：開啟註冊管理器檢視、重新整理和刪除註冊項；新物品 ID 按啟動流程生效。
  • /hdui tooltip (OP4)：手持物品的 Tooltip 編輯入口；詳見Tooltip 編輯。

營養組定義由資料包承載；編輯器中的建立或修改會寫入設定覆蓋層。舊 /hdgroups 已刪除。

07管理與指令

普通玩家可檢視自身面板；修改其他玩家數值或暫停營養組需要相應權限。

指令權限 / 用途與對象
/headiet 或 /headiet open玩家本人，無 OP 要求：把營養面板發給自己。
/headiet open <玩家>OP2：把營養面板發給指定玩家，不是執行者檢視該玩家的面板。
/headiet add <玩家> <組> <數值>OP4：增加目標玩家對應組數值；輸入 0–100，可帶小數。
/headiet subtract <玩家> <組> <數值>OP4：減少目標玩家對應組數值；輸入 0–100，可帶小數。
/headiet set <玩家> <組> <數值>OP4：把目標玩家對應組設為指定值；輸入 0–100，可帶小數。
/hdui groups [玩家]OP4：執行者開啟自己或指定玩家的營養管理屏，可調數值或暫停組；並非組定義編輯。
暫停組：暫停期間該組不隨進食增加，也不自然衰減；適用於劇情、新手保護或限時活動。恢復後按正常規則繼續。

08要點回顧

  1. 數值範圍為 0–100。小數保留，階段判定時四捨五入。
  2. 營養值隨飽食度消耗按衰減率下降。飽和度不參與；死亡不清空。
  3. 階段控制持續狀態，條件規則控制單次進食結算。實際組、閾值與效果以伺服器設定為準。
