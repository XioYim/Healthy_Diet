09 / SERVER ADMIN

先分清權威設定、用戶端顯示和啟動期註冊。

服主編輯時可從設定檔案、資料包覆蓋層和遊戲內編輯器三個入口著手；不同類型的修改具有不同的重新整理方式。

server.json資料包覆蓋層重載與同步
路徑說明：下列路徑相對於遊戲或伺服器實例的 config/healthy_diet/。文件說明目前原始碼支援的設定結構，是否實際啟用、資料包覆蓋順序及適用平台以所安裝檔案和伺服器為準。
需要逐欄位核對？新頁依檔案整理 server.json、display.json、營養資料包、物品/方塊、保存期限/溫度和外觀欄位，並給出預設值與重新整理方式。

02資料包定義與設定覆蓋層

物品與 Tooltip、營養組、階段、加成、品質、品級、方塊規則均支援資料包定義；透過 config/healthy_diet/datapack/ 提供本模組的本機覆蓋層。

路徑結構示意

config/healthy_diet/datapack/data/<命名空間>/healthy_diet/<類型>/<檔案>.json

例如 quality_levels/ 存品質定義、blocks/ 存右鍵方塊規則；其他類型要依遊戲內編輯器顯示的實際來源路徑定位。

編輯器儲存的設定覆蓋層與世界已有的資料包會共同參與載入。修改前應先確認目標項目的來源；設定覆蓋層不是把資料複製進舊的 config/healthy_diet/items/ 就能生效。

定位一個物品設定

先確認物品的命名空間和 ID，再找 data/<命名空間>/healthy_diet/items/<物品路徑>.json；Tooltip 同理使用 healthy_diet/tooltips/。編輯器寫出的 HD 覆蓋層與其他資料包的同一個項目可能同時存在：刪掉覆蓋層後，底下仍有資料包定義時會回落，而非保證徹底停用該物品。

原始碼依據：ConfigManager 的 pack 載入器、PackJsonLoader 與覆蓋層來源查詢。

03/hdreload 與其他指令

/hdreload 要求 OP4，只重載 Healthy Diet 自身可重載的設定和磁碟覆蓋層，並向線上玩家重新下發伺服器端權威內容；它不是 Minecraft 的全量 /reload。手動新增、修改或刪除覆蓋層檔案後，可依類型檢查重載結果。

玩家與物品管理/headiet 開啟營養面板；/hdui 管理手持物品和編輯入口，/hdui stage 管理營養階段。
查詢與說明/hdhelp 供玩家查指令語法；/hdtemperature 報告目前位置溫度分解；/hdtrust 管理保護白名單。

管理指令並非都對所有玩家開放，權限需依各指令註冊條件執行；/hdreload 要求管理權限等級 4。/hdconfig 是用戶端本機指令，執行指令本身需 OP4，不是專用伺服器主控台指令；非 OP 玩家仍可從其他介面進入本機外觀設定，詳見 設定介面圖解。

改完設定怎樣判斷

儲存或更新 HD 覆蓋層後執行 /hdreload，看指令回饋及方塊「已載入/變體/丟棄」計數，再用實際物品或方塊驗證。編輯器的某些儲存動作已自動呼叫本模組重載；如果改的是世界資料包或其他模組資源，仍要依其各自的載入流程處理，不能把 /hdreload 當成原版 /reload。

原始碼依據：HDReloadCommand、HDUICommand、HDClientCommands。

04哪些修改不能只靠重載

  • 1註冊新物品 ID：註冊定義在啟動階段生效；重載只能重算待啟動方案，不能臨時創造新的執行期 ID。
  • 2用戶端本機檔案：例如 display.json、本機漸層色、霧效等，不會由伺服器執行 /hdreload 強制遠端重讀。
  • 3堆疊上限：物品層級屬性修改需重新啟動；NBT 變體無法各自擁有不同堆疊上限。

多人伺服器若新增品質註冊物品，用戶端應在登入前取得一致的註冊清單和相關資源，然後依註冊流程重新啟動。不要把「伺服器端重載完成」當作「用戶端已經擁有新 ID」。

三步判斷重新整理方式：改伺服器可重載的物品、Tooltip 或營養資料 → 檢查 /hdreload 的載入回饋與下發；改玩家本機顯示/霧距 → 讓相關用戶端依本機流程重新讀取；新增或刪除 quality_registry/ 中的註冊 ID、變更堆疊上限 → 依啟動期註冊或物品屬性的要求重新啟動。前一類已下發，不等於後兩類也完成。
原始碼依據：QualityRegistryEntry、ItemConfig.stackSize、HDReloadCommand、ConfigManager。

05常用指令與權限

指令權限用途
/hdhelp所有人遊戲內完整指令索引，懸停看說明；點擊只填入輸入框。
/headiet所有人開啟自己的營養面板；檢視他人需 OP2，修改營養值需 OP4。
/hdinfo [物品]所有人查詢主手命中變體或指定物品的預設堆疊，開啟本機食物查詢器。
/hdtemperature所有人診斷目前溫度來源、方塊貢獻及可用連動。
/hdtrust所有人管理自己物品／容器的受信任玩家名單。
/hduiOP4開啟主手物品的設定中心。
/hdui createOP4管理營養組、品質等級與品級定義。
/hdui stageOP4管理階段、進入指令和條件加成。
/hdui groups [玩家]OP4管理玩家營養值與組狀態。
/hdui tooltipOP4開啟物品 Tooltip 編輯入口；存在變體時先選取對應行。
/hdui registryOP4管理啟動期註冊的品質物品；無需手持物品。
/hdset rarityOP2給物品指定或清除品級；具體參數查看 /hdhelp。
/hdcloneitemOP4將副手物品已經設定的項目局部覆蓋主手物品，而不是清空後完整替換。
/hdreloadOP4重載本模組設定並重新推送線上玩家；不觸發原版完整 /reload。
/hdconfig用戶端本機 OP4開啟用戶端設定畫面；專用伺服器主控台不註冊這條指令。
/titlepro 等OP2TitlePro 標題、範本、表格、清除和螢幕顏色覆蓋層。

/headiet add、subtract、set 修改值需要 OP4；/headiet clearaversion 解除指定物品的厭食記錄需要 OP2。/cleartoast 清自己的成就彈窗無須權限，帶其他玩家時需 OP2。具體參數和目標選擇請使用遊戲內 /hdhelp，不要照抄歷史文件裡的舊權限表。

原始碼依據：各指令註冊類的權限條件；實際以遊戲內 /hdhelp 和所安裝檔案為準。

06可選連動與重新啟動

可選模組用途
Jade對支援的掉落食物顯示保存期限資訊。
Legendary Survival Overhaul可提供環境溫度、體感等可用資料來源。
Ecliptic Seasons可提供季節、氣候與相關溫度／保鮮連動。
Refurbished Furniture可接入冰箱／冷凍櫃保鮮；NeoForge 還需其 framework。

這些是依功能使用的可選連動，不是基礎遊玩的前置；請依目標遊戲版本確認第三方模組本身的可用性。

什麼時候需要重新啟動：啟動期註冊的品質物品需要兩端擁有相符定義並在啟動時套用；修改啟動期內容不能只靠登入後同步或 /hdreload。用戶端本機顯示檔案的重新整理方式也不同於伺服器端玩法設定。
原始碼依據：QualityRegistryEntry、ConfigManager 與各連動模組的就緒判定。
