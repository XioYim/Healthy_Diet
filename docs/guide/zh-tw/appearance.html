01顏色方案與純色板

漸層方案在 colors/color_schemes.json 中以 ID 引用；純色板在 colors/solid_colors.json 中定義可選顏色。

例如營養組的配色可以引用一個漸層方案；品質和提示行也可以設定方案或直接使用純色。顏色表提供的是顏色來源，不決定某條提示是否顯示。

色卡範例A → B
範例顏色取自現行內建配色的其中一個方案；網頁色條不是遊戲截圖，也不代表每個營養組的實際顏色。
原始碼依據：ConfigManager 的配色檔案路徑、預設方案和 RarityConfig.scheme。

02靜態漸層與動態樣式

靜態文字可依字元分配漸層色，不隨時間變化；需要動態效果時才啟用對應開關。
動態目前支援 gradient、breathing、wave、pulse 等樣式；速度、步數與部分特有參數分別設定。

波動和脈衝還提供各自的步距或延遲；顏色順序反轉與動畫方向反轉也是兩項獨立設定。提示行可由多個文字段組成，每段擁有自己的配色與動畫參數。

參數怎樣配合

dynamic=false 時依字元顯示靜態漸層；開啟動態後，nameStyle 選動畫，speed 控制循環週期 (毫秒)，steps 控制顏色表的取樣精度。waveStep 只影響波紋，pulseDelay 只影響脈衝的逐字傳播。若使用分段文字，每段獨立配色與動畫，頂層文字和漸層參數不會覆蓋分段設定。

原始碼依據：TooltipLineConfig 的 dynamic、nameStyle、segments、colorReverse、dynamicReverse。

03顏色套用在何處

  • 1物品名稱與 Tooltip 附加行：可設定文字、漸層、分段、動態樣式及顯示條件；名稱行與附加行的限制不同。
  • 2品質與品級：品質可有覆蓋層、分段品質文字；品級影響稀有度標籤及相關物品名稱顏色。
  • 3厭倦資訊：使用 fatigue/fatigue_gradient.json 管理厭倦相關的提示色彩。
  • 4保存期限狀態：使用 shelf_life/schemes/ 中的保存期限顯示方案，區別於通用漸層色板。

改色前先找到目標行的來源：營養組色、物品名稱和自寫行不共用一個「全域文字色」開關；品質文字由品質定義引用，品級可依物品與 NBT 變體覆蓋。把通用漸層方案改掉會影響所有引用它的位置，想僅改一類提示應編輯那一類的綁定或單獨方案。

複製物品名稱配色：/hdset tooltip <來源物品ID> hand|<目標物品ID> (OP2) 將來源物品層級通用條目首行的配色方案與動態欄位複製到主手目標或明確物品 ID；不複製首行文字、星標、其他行或 NBT 變體。來源或目標的首行使用分段文字時會拒絕，不會直接複製分段配色；要逐段編輯請從 Tooltip 編輯入口操作。
原始碼依據：HDSetCommand.buildTooltipNode/doTooltipCopy、QualityLevelConfig、TooltipLineConfig。

04伺服器端規則與用戶端顯示

服主可以維護規則性內容並同步給線上玩家，例如食物提示版面、品質定義與保存期限顯示方案。用戶端本機的顯示設定和部分本機配色檔案不會因為伺服器端執行 /hdreload 就自動遠端重讀。

因此，修改外觀前先區分設定檔案是在伺服器端下發，還是需要每個用戶端自行安裝、重載或重新進入世界。對於註冊品質物品的自訂貼圖，用戶端還須擁有對應資源。

排查「服主改了，我卻沒變」

先看目標是在物品/品質等伺服器定義中，還是僅存在玩家用戶端本機配色；再確認用戶端擁有貼圖或字型資源。/hdreload 會重載並下發可同步的伺服器端規則，不會替玩家改寫本機檔案；網頁色卡也不會依伺服器資料自動更新。

路徑遷移：舊版 rarity_and_colors/ 與 shelf_env/ 目錄不是現行編輯路徑；請看實際安裝目錄的 colors/、fatigue/ 和 shelf_life/。
提示行怎樣顯示？先看普通、S 與 D 模式，再決定給某行套用何種配色。
