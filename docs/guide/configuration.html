REFERENCE / CONFIGURATION

配置项详解：先定位文件，再核对字段。

这一页把服务器的玩法开关、客户端本地显示、营养数据包、物品与方块定义、保质期和温度表集中成一份字段索引。先判断文件属于谁，再决定用重载、重进还是重启。

server.jsondisplay.json数据包字段刷新边界
默认值边界：表中的“默认”指字段在代码或新建配置中的初始值，不表示你的服务器正在使用该值。服务器文件、数据包和编辑器保存都可能覆盖它；带 _note_ 前缀的字段只是只读说明，修改不会生效。

01配置放在哪，归谁管

所有路径都相对于实例的 config/healthy_diet/；数据包路径另见 data/<命名空间>/healthy_diet/。先看“作用域”，再看“典型刷新方式”。

共 18 个配置入口；输入文件名、路径或字段名过滤。

文件 / 目录作用域负责内容典型刷新
server.json
gameplay / privacy / shelfMerge		服务端权威保质期总开关、联动开关、属性/效果刷新间隔、保护物品、测试日志、阶段命令隐私、堆叠合并门槛OP 页保存或编辑后 /hdreload
display.json客户端本地Tooltip 每行营养数、TitlePro 换行宽度、D 页宽度、温度单位、默认显示模式客户端显示设定保存；手改后重进客户端
colors/color_schemes.json两端外观命名渐变方案，供品质、营养组、提示行和保质期方案引用服务端 /hdreload；客户端本地文件按各端读取
colors/solid_colors.json两端外观编辑器纯色取色盘的色卡数组服务端 /hdreload；客户端本地文件按各端读取
fatigue/fatigue_gradient.json显示外观厌倦等级行、恢复进度行的方案与动画参数/hdreload
fatigue/fatigue_exempt.json服务端玩法吃下后不推进其他冷却食物恢复计数的物品 ID 列表/hdreload
shelf_life/seasons.json服务端玩法季节/节气保质期倍率、未加载 EC 时的回退倍率、显示名/hdreload
shelf_life/schemes/*.json两端显示保质期提示的文案模板、状态配色、符号、季节显示名/hdreload 并下发方案
temperature/block_heat.json服务端玩法非 LSO 分支的方块热源表：方块、状态条件、贡献温度/hdreload 或温度配置页保存
temperature/weather_offsets.json服务端玩法24 节气降雨/雷暴的温变偏移/hdreload 或温度配置页保存
temperature/day_night_offsets.json服务端玩法24 节气的正午/午夜温变幅度/hdreload 或温度配置页保存
temperature/season_temperature.json服务端玩法24 节气附加环境温度（叠加在 EC 气候上）/hdreload 或温度配置页保存
bottle_fills.json服务端玩法手持物品右键液体源方块后的消耗与产物规则/hdreload
fog_effects.json客户端本地拥有指定效果时的水下/岩浆雾距离各客户端读取本地文件；服务器重载不代改
item_rarities.json服务端/同步物品 ID → 品级 ID 的物品级兜底指定/hdreload；/hdset rarity 会写它
tooltip_templates.json编辑器本地[模板] 按钮使用的提示行模板数组编辑器读写本实例文件；不当作跨客户端同步内容
quality_registry/*.json启动期注册新增独立品质物品的来源、注册名、品质、食用与堆叠属性启动时生效；/hdreload 只重读待生效列表
datapack/data/<ns>/healthy_diet/
HD 覆盖层；世界数据包为 data/<ns>/healthy_diet/
items / tooltips / blocks / nutrition_* / quality_levels / rarities / effect_lines		数据包（世界 + HD 覆盖层）物品、提示、方块、营养、品质、品级和效果行定义；HD 覆盖层优先级最高世界数据包用 /reload；HD 覆盖层用 /hdreload
三个层次不要混：配置文件（config/healthy_diet/*.json）、数据包（data/.../healthy_diet/）和启动期注册（quality_registry/）的生效方式不同。把数据包文件复制到 config/healthy_diet/items/ 不会生成可由游戏读取的物品配置。
源码依据：ConfigManager 的路径常量与 loadAll、ServerConfigFile.migrate、QualityRegistryLoader。

02server.json：服务端权威分节

一个文件三个分节：gameplay、privacy、shelfMerge。旧版分离文件会在加载时迁入本文件，原文件移入 migration_backup/。

结构示意（省略只读 _note_ 字段）
{
  "gameplay": {
    "shelfTemperatureEnabled": false,
    "lsoIntegrationEnabled": true,
    "ecIntegrationEnabled": true,
    "proxyHeatstrokeEffect": true,
    "bonusUpdateTicks": 100,
    "effectUpdateTicks": 200,
    "ejectIllegalProtectedItems": false,
    "removeOwnerOnDeathDrop": false,
    "debugLogs": false
  },
  "privacy": { "sendCommandTextToAllPlayers": false },
  "shelfMerge": {
    "mergeRemainingMinutes": 5,
    "mergeTempThreshold": 10.0,
    "mergeColdFreshThreshold": 20.0
  }
}

gameplay：玩法与刷新间隔

字段类型 / 默认作用与边界
shelfTemperatureEnabledboolean / false保质期与温度系统总开关。关闭时暂停衰减、温度/冷鲜推进、过期产物与过期指令、温度拒食、温区效果和相关提示；已有物品数据保留，关闭时段从下次结算中扣除，不追溯补算。
lsoIntegrationEnabledboolean / true是否允许 hd:shelf 使用 LSO 的完整世界环境；不关闭其他 LSO 兼容。
ecIntegrationEnabledboolean / true是否允许 hd:shelf 直接使用 EC 气候和 HD 的 EC 季节倍率；不修改 EC 已由 LSO 提供的内容。
proxyHeatstrokeEffectboolean / true把 LSO 中暑镜像为 EC 中暑（服务端每 5 秒检查，仅借助 EC 的模糊效果）；无 LSO 中暑或带免疫时移除 EC 中暑。
bonusUpdateTicksint / 100属性加成结算间隔，单位 tick；限制在 1–1728000。默认约 5 秒。
effectUpdateTicksint / 200药水效果加成刷新间隔，单位 tick；限制在 1–1728000。默认约 10 秒。
ejectIllegalProtectedItemsboolean / false玩家持有从未被信任的保护物品时：true 丢到脚下；false 留在原位冻结并警告。默认关闭以免误判造成掉落消失。
removeOwnerOnDeathDropboolean / false死亡掉落：true 清除所有掉落物的保护数据；false 只给原本无主的掉落写入死者 UUID，已有主人的掉落保持原主人。
debugLogsboolean / false服务端测试日志开关；开启后输出方块右键与放置食物/分口食物的详细日志。/hdreload 应用。

privacy：阶段命令文本

字段类型 / 默认作用与边界
sendCommandTextToAllPlayersboolean / false默认只向权限 4 的玩家下发阶段命令文本；true 时非 OP 也收到完整阶段配置，可用于公开玩法说明。它不改变命令执行权限。

shelfMerge：堆叠合并门槛

字段类型 / 默认作用与边界
mergeRemainingMinutesint / 5两堆剩余保质期的最大差（分钟）仍可合并；限制在 1–1440。
mergeTempThresholdfloat / 10.0两堆物品温度的最大差（°C）仍可合并；限制在 0–100，NaN 差值忽略。
mergeColdFreshThresholdfloat / 20.0两堆冷鲜进度（0–100）的最大差仍可合并；限制在 0–100。
保存边界：OP 配置页的「服务端显示」当前往返的是 gameplay 分节；privacy 与 shelfMerge 需要编辑 server.json 后执行 /hdreload。文件只读时配置页保存失败，不会改内存中的权威值。
源码依据：ServerGameplayConfig、ServerPrivacyConfig、ShelfMergeConfig、ServerConfigFile、ConfigManager.saveServerGameplayConfig。

03display.json：客户端本地偏好

这份文件只影响当前客户端的外观与编辑默认值，不参与服务器玩法同步。服务端下的玩法开关在 server.json 的 gameplay，不要写回这里。

字段类型 / 默认作用与边界
nutritionPerLineint / 6Tooltip 每行最多显示的营养条目数；1 = 每组单行，数值越大越紧凑。编辑器范围 1–100。
titleproWrapWidthint / 1000TitlePro 标题换行宽度（像素）；编辑器范围 1–100000。
defaultConditionalGainEnabledboolean / true新建条件营养规则时“实际增益”的默认开关；只初始化草稿，不是已保存规则的运行开关。
infoGapWidthint / 20D 模式右对齐提示行左右内容的固定间距；编辑器范围 0–100000。
maxInfoWidthint / 320D 模式信息面板的最大宽度（像素），超出换行；S 模式不受此上限限制。编辑器范围 0–100000。
showUnifiedPotionStyleboolean / false统一药水样式总开关；关闭时绕过所有物品和默认的“强制统一”选择。
enableEnchantmentInfoboolean / trueD 模式自动显示附魔书说明（按 Enchantment Descriptions 约定读取语言键）。
enablePotionInfoboolean / trueD 模式药水/效果信息总开关。关闭后 D 页不显示原版药水说明、HD 效果行、外部模组效果行、属性统一段和 LSO 口渴行；普通模式紧凑效果行、温区效果行、JEI/手写 D 文本和附魔说明不受影响。
hideSystemPrefixesboolean / false只隐藏 HD 自动添加的行首符号及其间距；不隐藏玩家手写名称、行内分隔符或分段文本。
temperatureUnitstring / celsiuscelsius 或 fahrenheit；只影响本客户端提示/HUD，配置文件和编辑器仍用摄氏。非法值回落摄氏。
temperatureUnitChosenboolean / false本客户端是否已明确选择温度单位；用于首次提示，不上传同步。
groupLocalizePromptedboolean / falseOP 的营养组名称本地化提示是否已在本客户端显示或回答；仅本地记录。
defaultEffectsShiftOnlyboolean / false新建药水效果行的默认显示模式：false 常显，true 仅按住 Shift；已保存的行保留自己的设置。
defaultForceUnifyboolean / false新建效果行时“强制统一”的默认值；只对已有 Tooltip 配置/数据包条目的物品生效。
defaultFoodBarDisplayModestring / alwaysalways 常显、shift 仅 Shift、info 仅 D 页、off 整体停用并退回原版饮食值行；只影响没有自身提示配置的物品和新建行。
已移除的旧键：面板宽度/偏移、文字阴影等旧外观字段不再由 display.json 控制；不要按旧教程写回。文件以 _note_ 开头的说明字段只读。手改本文件后需要重进客户端；在“客户端显示设定”中保存会立即写回。
源码依据：DisplayConfig、HdDisplayConfigScreen、ConfigManager.loadDisplayConfig。

04营养数据包：组、阶段、加成

三类文件都在 data/<命名空间>/healthy_diet/ 下，以营养组 ID 关联；HD 覆盖层写在 config/healthy_diet/datapack/。文件名就是组 ID，最多 64 个组。

类型路径文件内容
营养组nutrition_groups/<组id>.json一个 GroupDefinition 对象：名称、符号、排序、颜色、衰减、初始值、获取倍率和可用条件。
阶段nutrition_stages/<组id>.jsonstages 数组与 hideAutoBonus；文件键是所属营养组。
加成nutrition_bonuses/<组id>.jsonremark 与 bonuses 数组；每条含条件、属性加成和效果加成。

营养组字段

字段默认说明
displayNameGroup界面和提示中的组名；实际默认组由内置数据包提供中文名。
nutritionSymbolΨ 营养行前缀符号；空白会回落到默认符号并补一个空格。
order0营养界面排序，升序；相同序号按组 ID 字母序。
color#FFFFFF#RRGGBB 为纯色；其他字符串按 color_schemes.json 的方案键处理。
colorStylenull方案键配色时的动画参数：dynamic、nameStyle、speed、steps、waveStep、pulseDelay、两个反转开关及 bold/italic/underlined。纯色时忽略。
decayRate6.0自然衰减速率：每消耗 1 点饱食度降低 1/decayRate 营养值；小于等于 0 视为不衰减。
icon""可选图标资源名；留空使用界面默认显示。
initialValue0新玩家或新增该组时的初始营养值，0–100。
gainMultiplier1食物对该组的正负变化都乘此倍率；允许 0，负数/NaN/Infinity 视为非法并回落 1。最终值仍夹在 0–100。
enabledtrue组总开关。关闭后该组对所有玩家隐藏、冻结、停止衰减与条件/加成；恢复后继续。
requiredPlayerTag""要求玩家拥有的计分板标签，精确匹配；空 = 不限制。不是物品/方块标签。
requiredModId""要求服务端已加载的 modid；空 = 不限制。未安装时该组对该玩家禁用，可用于整合包预置可选联动。
nutritionTipColors自动生成四个独立提示颜色槽（普通/条件 × 增益/损失）；nutritionTipColorsCustomized 决定增益槽是否跟随组名颜色。手改前建议先用编辑器。
营养组示例（文件名即组 ID）
{
  "displayName": "水果",
  "nutritionSymbol": "Ψ ",
  "order": 2,
  "color": "a",
  "decayRate": 6.0,
  "initialValue": 0,
  "gainMultiplier": 1.0,
  "enabled": true
}

这里的 "a" 是方案键示例，不是要求所有组都用它。

阶段字段

字段默认说明
stages[].min / max0 / 100闭区间边界；实际判定先把营养值四舍五入到整数。相邻阶段应连续，编辑器会拒绝重叠和空档。
stages[].label""阶段名称。
stages[].tooltip[]该阶段的附加提示文本行。
stages[].commands[]进入/处于该阶段时按服务端规则执行的命令；文本只向 OP4 或开启隐私开关的服务器下发。
hideAutoBonusfalse文件级开关；true 时该组所有阶段悬停不再自动追加范围标题和加成预览。

加成字段

字段默认说明
remark""编辑器列表中的备注名，不参与结算；留空显示文件名。
bonuses[].conditions{}组 ID → {min,max} 的映射；同一加成内多个条件按“且”判断。
bonuses[].attributeBonuses[][]attribute（默认 minecraft:generic.max_health）、operation（add/multiply_base/multiply_total，默认 add）、value。
bonuses[].effectBonuses[][]effect、level（0 = I 级）、duration（tick，默认 200）、showParticles（默认 false）。
源码依据：GroupDefinition、StageConfig、GroupBonusConfig、ConfigManager.loadGroupsFromPacksChecked、loadStageConfigsFromPacksChecked、loadGroupBonusesFromPacksChecked。

05物品、提示、方块与品质

这些类型的字段较多，下面只给字段组和入口；具体玩法解释分别放在营养、保质期、Tooltip 和品质章节，避免同一字段在三处写出不同含义。

数据包类型路径主要字段 / 说明相关章节
物品items/<物品路径>.json营养、效果、厌倦、保质期、指令、条件规则、堆叠、品质、品级、NBT 变体营养 · 厌倦 · 保质期
Tooltiptooltips/<物品路径>.json名称覆盖、附加行、显隐开关、NBT 变体Tooltip · 显示美化
方块blocks/<方块路径>.json状态/主手/潜行条件、营养、效果、命令、冷却、取消原版交互小功能
品质quality_levels/<id>.json字符串 ID、名称、纯色/方案、分段、覆盖层品质
品级rarities/<id>.json品级 ID、分段、色表或方案、动画参数显示美化
效果行effect_lines/<效果id>.json按效果 ID 固定的提示行配色与修饰；仅在物品效果行“强制统一”时压过物品设置Tooltip

物品配置的字段组

字段组说明详见
nutrition组 ID → 营养变化量；正负都乘组获取倍率，再与终身衰减和分口份数结算。营养值
effects食用后药水效果，含等级、tick 时长、概率、粒子与新鲜度曲线。TitlePro 与效果
foodCooldown短期厌倦：maxUses、cooldownCount、cooldownMinutes、restoreHunger。食物厌倦
foodFatigue终身衰减：lossStart、aversionCount；两者都设置才启用线性衰减。食物厌倦
shelf基础时长、温度曲线、维度倍率、冷鲜/保冷、环境温变、食用温度效果。保质期
onEatCommands / suppressEffects进食指令与清除物品自带效果；分别有独立延迟。进食反馈
conditionalRules营养条件 → 目标营养变化/命令/提示；一条规则整体保存。条件规则
stackSize物品级堆叠上限，0 = 原版默认；重启生效。NBT 变体不能拥有独立堆叠上限。服主手册
quality / rarity绑定品质 ID 与品级 ID；品级按“命中变体 → 通用条 → item_rarities.json → 原版”的优先级取。品质与品级
nbtLock / variantNameNBT 变体锁与备注；空 nbtLock 是通用条，非空是变体。NBT 变体

方块右键变体字段

字段默认说明
state{}方块状态属性子集；空 = 匹配该方块任意状态。状态属性越多，匹配优先级越高。
handanyany、empty（主手为空）或 item（主手物品需命中 items）。
items[]物品 ID 或 #标签 列表；仅 hand=item 时参与匹配。
consumeItem0触发时消耗主手数量；创造模式不消耗，数量不足视为条件不满足。
sneakanyany、require 或 forbid。
cooldownTicks20同一变体的触发冷却，0–72000 tick；0 = 不写冷却。
cancelVanillafalse匹配后是否取消原版方块交互；为 true 时长按会去重，为 false 时每次原版重发都要结算。
nutrition{}组 ID → 变化量；受组获取倍率影响，但没有终身衰减和分口。
effects / effectDelay[] / 0效果列表与施加延迟（tick）；方块交互没有物品保质期，曲线效果不生效。
commands / commandsAtBlock[] / false指令可写 {x} {y} {z}；true 时执行位置改为方块中心。
titles / commandDelay[] / 0TitlePro 标题与命令共用延迟（tick）。
禁用与变体：items 与 tooltips 支持 .json.disabled 禁用约定；blocks 没有这种约定。NBT 变体可以覆盖食物/提示字段，但 stackSize 是物品单例属性，变体中会被强制为 0。
源码依据：ItemConfig、ItemTooltipConfig、BlockConfig、QualityLevelConfig、RarityConfig、EffectLineConfig、ConfigManager.findBlockVariant 与数据包加载器。

06保质期与温度环境字段

物品的 shelf 字段控制单件食物；shelf_life/ 与 temperature/ 下的文件控制季节、环境温变和显示方案。字段默认值适合新建，实际物品常在默认数据包中覆盖。

物品 shelf 顶层字段

字段默认说明
durationMinutes60基础保质时长，按分钟存储，1–99999。编辑器的 durationUnit 只是显示单位，不改变存储。
durationUnitminutesminutes、hours、days（现实日，1440 分钟）或 game_days（20 分钟）。非法值回落 minutes。
resultItemminecraft:air过期后替换成的物品；空气表示消失。
inheritTemperatureOnExpiretrue替换时让产物继承过期瞬间温度；只继承温度，产物保质期仍从 0 开始。
expireCommand""玩家持有物品过期时以持有者为上下文执行的命令；掉落物/容器内过期不触发，不写入物品 NBT。
baseDecayMultiplier1.0基础变质倍率，非负。
temperatureCurves[]温度 → 变质倍率曲线，最多 16 条；字段见下。

07外观方案与小工具

这些文件多数是共享外观或本机小工具，不改变营养/保质期结算。改配色前先确认目标行引用的是哪个方案键。

文件结构与关键字段边界
colors/color_schemes.json方案 ID → { "colors": ["#RRGGBB", ...] }；方案 ID 被营养组、品质、提示行、品级和保质期方案引用单个颜色可用，但两个以上才形成可见渐变；改共享方案会影响所有引用位置。
colors/solid_colors.json["#RRGGBB", ...] 色卡数组供编辑器纯色选择；非法项被忽略，不会生成颜色。
fatigue/fatigue_gradient.jsonenableGradient；fatigueLevelGradient 与 fatigueRecoveryGradient，各含 scheme、stars、dynamic、speed、steps、nameStyle、waveStep、pulseDelay、两个反转开关和修饰只影响厌倦提示的颜色与动画，不改变冷却/厌食阈值。
fatigue/fatigue_exempt.json物品 ID 字符串数组；默认含腐肉、药水、蜘蛛眼、牛奶桶吃下这些物品不会推进其他冷却食物的恢复计数；不是“吃它永不厌倦”的配置。
tooltip_templates.json模板数组：text、scheme、stars、shiftOnly、dynamic、nameStyle、speed、steps、waveStep、pulseDelay、两个反转开关编辑器 [模板] 按钮读取；属于本实例编辑辅助，不把它当作跨客户端下发内容。
item_rarities.json物品 ID → 品级 ID 的映射物品级兜底；命中 NBT 变体的品级在物品配置条目中，优先级更高。/hdset rarity clear <物品ID> 删这里。
bottle_fills.json{ item, fluid, result, resultNbt } 数组只匹配液体源方块；创造模式不消耗也不产出；resultNbt 解析失败仍给结果物品，仅不带 NBT。
fog_effects.jsoneffects（默认夜视）、waterFogStart 80、waterFogEnd 160、lavaFogEnd 6客户端本地；改变雾距离而非雾颜色；效果结束前平滑回退；服务器重载不代改本地文件。
effect_lines/<效果id>.jsonid、scheme、dynamic、nameStyle、speed、steps、waveStep、pulseDelay、两个反转开关和修饰只在物品药水效果行开启“强制统一”时压过物品自身设置；文本固定为效果名。

08游戏内入口与刷新方式

同一个“保存”在不同位置含义不同：客户端本地文件、服务端权威分节和启动期注册不能互相替代。

游戏内配置菜单

入口覆盖内容权限 / 生效
客户端显示设定display.json：Tooltip 布局、温度单位、默认显示模式所有玩家；保存写本机文件，立即应用
服务端显示server.json 的 gameplay：保质期总开关、联动、刷新间隔、保护物品、测试日志OP4；服务端保存并回执，在线玩家收到投影
温度与环境季节倍率、方块热量、雨雪/昼夜/节气温度OP4；按各分页读取和保存
群系温度与已安装的温度/群系兼容相关的编辑入口OP4；具体项随环境变化

改完之后做什么

只改服务端规则例如 server.json、营养组/阶段/加成、物品、方块、品级、颜色和保质期方案：保存或编辑后执行 /hdreload，让本模组重新读盘并向在线玩家重发权威内容。
只改本机外观例如 display.json、客户端 fog_effects.json、本地提示模板：在各客户端处理；服务器执行 /hdreload 不会替你改这些本地文件。
修改内容推荐动作为什么
server.json gameplay / privacy / shelfMerge配置页保存，或编辑后 /hdreload服务端权威值在加载时读入；保存路径会写分节并重推。
display.json、本地雾效、本地模板在对应客户端保存；手改后重进客户端不参与服务端同步，/hdreload 不远程重写本地文件。
营养组 / 阶段 / 加成、物品、提示、方块、品质、品级、效果行保存后 /hdreload；世界数据包改动可用原版 /reloadHD 覆盖层由 /hdreload 以磁盘为准重建；世界数据包由资源管理器刷新。
新增/删除 quality_registry/ 条目两端同步定义后重启物品注册只发生在启动阶段；/hdreload 只重算待生效列表。
物品 stackSize重启堆叠上限是物品单例属性；NBT 变体不能各自覆盖。
共享客户端资源（贴图、字体等）分发到各客户端服务端配置只能描述引用，不能把资源推送到客户端。
不要把 /hdreload 当成原版 /reload：它只重载 Healthy Diet 自身可重载的配置和 HD 覆盖层；原版数据包/资源包、其他模组的资源以及客户端本地文件仍按各自流程处理。
需要确认具体物品字段？营养、厌倦、保质期、Tooltip 和品质章节分别解释字段的玩法含义；本页只负责“字段在哪、默认是什么、改完怎么生效”。
