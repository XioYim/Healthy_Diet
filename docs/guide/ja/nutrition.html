栄養値：数値、ステージ、条件ルール。

このページでは計算順に栄養グループ、減少、ステージ、ボーナス、条件ルールを説明します。画面と数値は例であり、実際のルールはサーバー設定で決まります。

一般的な既定設定には6グループあります：乳製品、果物、穀物、タンパク質、糖分、野菜。サーバーは追加・削除・改名・順序変更ができます。

01仕組みの概要

各栄養グループは独立した0–100の数値軸です。食べ物は複数グループに同時に影響でき、満腹度が減ると各グループが設定された減少率で減ります。

同じ食べ物でもグループごとの寄与は異なります。たとえばリンゴは果物と糖分を同時に増やします。食べ物ごとの違いが食生活の構造を作ります。

林 リンゴ 例の食べ物
→
果物 +26
糖分 +12
例：1つの食べ物が複数グループに影響できます。バーは計算後の例であり、サーバーの既定設定ではありません。

栄養パネルの例

H を押すと栄養パネルが開きます。グループ名、配色、ステージ範囲は Forge メインライン内蔵 JSON から取得しています。各ステージにホバーまたはキーボードフォーカスすると、実際に設定されたボーナスプレビューを確認できます。既定ステージには手書きの名前や説明がないため、ツールチップには範囲、設定されたボーナス、必要なクリックコマンド案内だけが表示されます。

栄養状態 · 設定例H で開く
HTML による模擬画面で、ゲームのスクリーンショットではありません。6つの色ブロックはアイテムアイコンを置き換えるものではありません。表示値は例のプレイヤー状態で、既定の初期値ではありません。ステージ区画にマウスを合わせるか Tab でフォーカスすると、その区間の実際の既定ボーナスを確認できます。「確認完了」にホバーすると、この例の値で現在有効なボーナスを確認できます。ここでゲームコマンドが実際に実行されることはありません。
設定ソース：nutrition_groups.json と既定データパックの nutrition_stages/*.json、nutrition_bonuses/*.json。配色は color_schemes.json から取得します。たとえば既定の野菜グループは initialValue が42、decayRate が6です。図の55%は46–60区間のボーナスを示すための例です。ボーナスのツールチップは HealthyDietScreen と BonusTooltipUtil に基づき、任意の説明を既定設定に書き込むものではありません。
数値体系：満腹度と栄養値は互いに独立しています。満腹度は空腹と摂取に、栄養値は長期的な食生活構造に使います。

02増加と減少

摂取による増加と満腹度による減少は、2つの独立した計算経路です。

摂取による増加量はおおよそ 食べ物の基本値 × そのグループの取得倍率 です。生涯食物嫌悪がある場合はさらに減少係数を掛けます。計算後は0–100にクランプされます。管理者コマンド、自然減少、初期値は取得倍率を通りません。

4
20
栄養値の減少 5.0 ポイント 式：満腹度 ÷ 減少率。満腹度のみを計算し、隠し満腹度は計算しません
残り 95.0
スライダーは減少式のデモです。計算は100から始まり、実際の初期値を示すものではありません。
  • 1範囲は常に0–100。栄養値は小数を保持でき、計算後に上下限でクランプされます。
  • 2ステージ判定は整数。現在値を四捨五入してからステージに一致させます。たとえば59.6は60として扱います。
  • 3死亡しても栄養値は消えません。リスポーン時にデータはプレイヤー能力としてコピーされます。
例と設定：減少率、初期値、取得倍率はサーバーが調整できます。実際の値は /headiet パネルとサーバー設定に準拠します。

03ステージ

ステージは栄養値の区間と関連動作です。ステージのタイトル、説明、クリックコマンドはステージページで編集し、グループ横断の継続効果と属性ボーナスは独立した効果ページで区間条件ごとに設定します。

ステージ境界は整数を使います。エディターは隣接区間を検証し、値がステージ間の空白に入らないようにします。判定時は先に四捨五入し、その後で区間に一致させます。

低 0–29
中 30–69
高 70–100
整数判定：60 現在の例のステージ：中
ステージ名と 0–29 / 30–69 / 70–100 は例です。サーバーはより多くのステージや異なる境界を設定できます。

ステージの設定項目

名前と説明 ステージを識別し、現在の状態を説明します。説明は栄養パネルのツールチップに表示されます。
クリックコマンド プレイヤーがステージをクリックしたときに実行します。管理者権限で動作し、出力は抑制されます。
自動ボーナスプレビュー ステージに設定された属性と効果をツールチップへ自動追加します。重複表示を避けたい場合は無効にできます。
クリッククールダウン：ステージコマンドは同じプレイヤーで 1.5秒 の間隔が必要で、サーバーが再検証します。コマンドはサーバー管理者が設定します。出所不明のステージコマンドをクリックしないでください。

ゲーム内 /hdui stage：ステージ／コマンド／説明

OP4 が必要です。左側には有効な栄養グループだけが表示されます。以下の3つの図はそれぞれ1つの Tab 構造を示します。図内のタブリンクは対応する図へ移動できます。図内のボタンと入力欄は読み取り専用の例で、ゲーム設定を保存することはできません。

画面根拠：StageManageScreen.buildContentTabs/buildEffectButton/buildStageBottomButtons、buildCommandRows/buildDescriptionRows、現在の zh_cn ラベル。

04ボーナスと連動

独立した効果ページでは、1つまたは複数の栄養グループの区間組み合わせに、継続的な属性修飾子とポーション効果を設定できます。すべての条件を満たすと連動ボーナスが発動します。食べた後の単発ポーション効果を編集するページではありません。

属性ボーナス たとえば最大体力、移動速度。既定では約5秒ごとに評価され、サーバーが調整できます。
ポーション効果 たとえば体力再生、ダメージ耐性。既定では約10秒ごとに更新されます。既定の周期では、効果時間を10秒より長くしないと途切れます。
連動ボーナス 複数グループの区間条件を同じ設定に書き、すべて満たすと有効になります。
果物30–69
+
野菜30–69
+

すべて満たす追加効果を付与
連動条件は AND 関係です。いずれかのグループが区間を外れると成立しません。
ステージを離れた後：ボーナスは維持されず、更新周期で更新されます。属性修飾子は回収され、ポーション効果は残り時間に応じて終了するため、効果時間は更新周期に合わせる必要があります。

独立効果と属性ボーナスページ

ステージページの緑色「効果」入口から入ります。有効なグループだけが表示されます。グループのバーでステージをクリックすると開始/終了を埋められ、手入力後は「カスタム」を押して範囲を送信します。Shift クリックでステージの選択を追加/解除できます。複数グループを選択した場合、選択した各区間組み合わせを nutrition_bonuses に個別保存します。これらの条件を単一グループのステージ表と解釈しないでください。

画面根拠：EffectManageScreen.buildGroupRangeControls/buildBottomButtons/saveEffectRows と現在の zh_cn ラベル。アイテムの単回摂取効果は 摂取ポーション効果 を参照してください。

05条件ルール

通常の栄養計算は摂取時に直接実行されます。条件ルールは通常計算の後、栄養区間に基づいて追加変化やコマンドを決めます。

条件ルールは複数の栄養グループを同時に確認でき、すべて満たした場合に任意のグループへ加減算、コマンド実行、またはその両方を行います。条件グループと対象グループは異なっていても構いません。

食べ物を食べる先に通常栄養値を計算
→
条件を確認複数区間をすべて満たす必要あり
→
結果を実行栄養変化 / コマンド
→
0–100にクランプ境界でクランプ
条件ルールは通常栄養計算の後に実行されます。同じ食べ物が同じグループに通常値と条件変化の両方を設定している場合、2つの処理が順に計算されます。

条件ルール1件 · 例

発動条件 肉類 0–86 AND 果物 30–100
栄養変化 肉類 +20 糖分 -5
任意 コマンド実行 通知表示 取得倍率

よくある2つの設定

上限を制限

条件：肉類が 0–86。対象：肉類 +20。

現在80で食べると最大86まで。現在90では条件が成立せず増加しません。

減少補正

条件：肉類が 86–100。対象：肉類 -30。

現在95で食べると86付近まで下がって止まり、低値区間へ入り続けることはありません。

同じグループの重複計算：同じ食べ物が同じグループに通常栄養値と条件変化の両方を設定している場合、2つの処理が順に実行されます。通常はどちらか一方の表現だけを残し、重複計算を避けてください。

06エディターとバリアント

アイテムを持って /hdui を入力すると、そのアイテムの設定入口が開きます。

エディターは栄養、食べ飽き、渇き、満腹度、スタック、品質、保存期間、効果、コマンド、条件、効果解除を統合しています。以下の図はレイアウト例で、実際のスクリーンショットではありません。

アイテムエディター · 例アイテムを持って /hdui

もう1つの入口：/hdui create の栄養値 Tab

/hdui create は OP4 が必要で、作成/変更するのは栄養グループ定義であり、特定プレイヤーの現在値を変更するものではありません。品質とレアリティは同じエディターの別の2つの Tab にあります。品質図、レアリティ図へ直接移動できます。

画面根拠：HdCreateScreen.buildGroupForm/buildHeaderButtons/groupErrors。新規アイテム登録は 登録マネージャー を参照してください。

NBT バリアント：同名アイテムの独立設定

同じアイテムを NBT で複数のバリアントに分け、各バリアントが独立した設定を保存できます。摂取時は一致したバリアントの設定を使います。たとえば同じポーションの異なる NBT に異なる栄養を設定できます。

バリアント A 回復ポーション
果物 +8
糖分 +4
バリアント B 俊敏ポーション
タンパク質 +6
野菜 +3
バリアント値は例です。各バリアントは独立した設定を保存し、共通エントリを自動継承しません。
スタック上限はアイテムレベル属性：同じアイテムの異なるバリアントに異なるスタック数を設定することはできません。渇き値などのアイテムレベル設定も同様です。

よく使う入口

  • /hdui create (OP4)：栄養グループ、品質、レアリティ定義を作成/変更。グループ ID は作成後に自由に変更できず、独立アイテムも登録しません。
  • /hdui stage (OP4)：ステージ/コマンド/説明編集を開き、緑色「効果」から独立ボーナスページへ移動します。
  • /hdui groups [プレイヤー] (OP4)：実行者が自分または指定プレイヤーの数値管理画面を開きます。通常の栄養パネルではなく、グループ定義も作成しません。
  • /hdui registry (OP4)：登録マネージャーを開き、登録項目の表示、更新、削除を行います。新規アイテム ID は起動手順で有効になります。
  • /hdui tooltip (OP4)：手持ちアイテムのツールチップ編集入口です。詳細はツールチップ編集を参照してください。

栄養グループ定義はデータパックが担当し、エディターでの作成や変更は設定オーバーレイに書き込まれます。旧 /hdgroups は削除されました。

07管理とコマンド

一般プレイヤーは自分のパネルを表示できます。他のプレイヤーの値を変更したり、栄養グループを一時停止したりするには権限が必要です。

コマンド権限 / 用途と対象
/headiet または /headiet openプレイヤー本人、OP 不要：栄養パネルを自分に送ります。
/headiet open <プレイヤー>OP2：栄養パネルを指定プレイヤーに送ります。実行者がそのプレイヤーのパネルを見るのではありません。
/headiet add <プレイヤー> <グループ> <数値>OP4：対象プレイヤーの対応グループ値を増やします。入力は0–100、小数可。
/headiet subtract <プレイヤー> <グループ> <数値>OP4：対象プレイヤーの対応グループ値を減らします。入力は0–100、小数可。
/headiet set <プレイヤー> <グループ> <数値>OP4：対象プレイヤーの対応グループ値を指定値に設定します。入力は0–100、小数可。
/hdui groups [プレイヤー]OP4：実行者が自分または指定プレイヤーの栄養管理画面を開き、値を調整したりグループを一時停止できます。グループ定義編集ではありません。
グループの一時停止：一時停止中、そのグループは摂取で増えず、自然減少もしません。ストーリー、初心者保護、期間限定イベントなどに使えます。再開後は通常ルールで続きます。

08要点の振り返り

  1. 数値範囲は0–100。小数は保持され、ステージ判定時に四捨五入されます。
  2. 栄養値は満腹度消費に応じて減少率で下がります。隠し満腹度は関与せず、死亡しても消えません。
  3. ステージは継続状態を、条件ルールは単回摂取の計算を制御します。実際のグループ、しきい値、効果はサーバー設定に準拠します。
