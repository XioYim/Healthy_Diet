03 / QUALITY & RARITY

品質、レアリティ、独立アイテムをそれぞれ設定する。

品質は付加的な品質表示を決め、レアリティはアイテムのレアリティ表示を変えます。品質アイテムを登録すると新しいアイテム ID が作成されます。3つは同じ設定ではありません。

品質バインディングレアリティ上書き独立アイテム ID
重要な区別：既存アイテムの品質/レアリティを変更することは、新しいアイテムを登録することとは異なります。独立登録アイテムの追加・削除は起動時の登録に関わります。ホットリロード定義と新規アイテム登録を混同しないでください。

013つの機能の違い

品質文字列 ID で品質テキスト、セグメントスタイル、任意のオーバーレイを定義します。既存アイテムは quality フィールドでバインドできます。
レアリティアイテム名とレアリティ表示に使います。カスタムレアリティまたはバニラのレアリティを選べます。新しいアイテム ID は作成しません。
登録アイテム元アイテムを基に独立した ID を登録し、品質、名前、モデル、摂取属性、スタック上限を指定できます。
ソース根拠：ItemConfig.quality、ItemConfig.rarity、QualityRegistryEntry。

02品質定義とバインディング

品質 ID は文字列で、旧来の数値レベルではありません。有効な ID は1～64文字の小文字英字、数字、_、-、. です。

各品質の定義はデータパック data/<名前空間>/healthy_diet/quality_levels/<id>.json から読み込みます。テキスト、色または配色スキーム、セグメントテキスト、オーバーレイテクスチャを設定できます。定義した ID は既存アイテムの「品質バインディング」で選択でき、新規登録アイテムから参照することもできます。

設定パスの例

config/healthy_diet/datapack/data/healthy_diet/healthy_diet/quality_levels/fresh.json

ここでの fresh は有効なファイル名の例であり、必ず存在する既定の品質ではありません。

/hdui create を開くと品質定義を管理できます。アイテムを持って /hdui を開くと、そのアイテムに品質をバインドできます。定義の変更は更新・同期できますが、オーバーレイが見えるかどうかはクライアントのリソースと使用する表示コンポーネントによります。

画面根拠：HdCreateScreen.buildQualityForm/qualityErrors。このページのラベルは現在の zh_cn を参照しています。
操作順序

先に品質 ID を作成または確認し、既存アイテムに quality 参照を設定します。定義を作成するだけではすべての食べ物に品質が自動付与されません。存在しない ID を入力しても、対応するテキストやテクスチャが勝手に生成されることはありません。その ID を既にバインドしているアイテムは、更新後の品質定義を使用します。

ソース根拠：QualityLevelConfig.ID_PATTERN、segments、overlay、HdCreateScreen。

03レアリティ：アイテムにレア度を指定する

レアリティにはテキスト、配色、アニメーションを設定できます。アイテムへのバインドは /hdset rarity <レアリティid> [アイテムID] (OP2)、またはアイテムエディターから行います。上書きの解除は /hdset rarity clear [アイテムID] (OP2) です。明示的なアイテム ID を付けない場合はメインハンドで一致する NBT バリアントが対象になり、ID を付けるとアイテムレベルのフォールバックを操作します。

/hdui create (OP4) の「レアリティ」タブではレアリティ定義を管理します。ID は1～64文字の小文字英字、数字、_ のみ使用できます。セグメントテキストを編集した後、新規作成・変更・削除ができ、状態を確認できます。有効な新規レアリティ定義はプロキシ列挙により即時反映・同期されます。過去の「再起動待ち」表示をすべてのレアリティに共通の条件と考えないでください。定義が無効な場合はテキストと配色を確認する必要があります。

画面根拠：HdCreateScreen.buildRarityForm/rarityErrors、CPacketCreateEntry.RARITY_ID_PATTERN、現在の zh_cn ラベル。
同じアイテムの異なるバリアントに配色する

まずアイテムに共通レアリティを設定し、必要に応じて特定の NBT バリアントに個別指定します。そのバリアントに一致するアイテムだけがバリアント上書きを使用し、それ以外は共通レアリティを使います。一致するバリアントのレアリティを解除するには、そのバリアントを持って ID なしの /hdset rarity clear を実行します。アイテム ID 付きのコマンドは item_rarities.json のアイテムレベルフォールバックを解除します。解除後も次の層のソースを確認する必要があり、「上書き解除」は白い名前になることを保証しません。

  • 1一致する NBT バリアントが優先されます。未設定の場合は共通エントリ、アイテムレベルの item_rarities.json、最後にアイテム本来のレアリティへ順にフォールバックします。
  • 2新規レアリティ定義はプロキシレアリティ経由で表示・ホット更新できるため、画面の過去の「再起動が必要」表示をすべてのレアリティの実際の要件と見なさないでください。
  • 3レアリティの変更はレア度とアイテム外観だけに影響し、新しい品質登録アイテムを勝手に生成することはありません。
ソース根拠：ItemConfig.rarity、RarityManager.DATAPACK_PROXY_ID、HDSetCommand。

04独立登録アイテム

/hdui registry (OP4) で品質レジストリマネージャーを開き、登録項目の表示、更新、削除ができます。/hdui create の3つのタブは新しいアイテムの登録を担当しません。各登録定義は元アイテムを指し、登録名、品質 ID、摂取または飲用アクション、スタック数などを設定します。

既存アイテムへのバインドとは異なり、登録項目は新しい healthy_diet アイテム ID を生成します。アイテム登録は起動段階で行われます。定義はローカルの config/healthy_diet/quality_registry/*.json に保存されます。マネージャーが変更するのは次回起動時に有効になる計画であり、/hdreload で全く新しい ID を現在のアイテムレジストリに即時追加することはできません。

定義から配布可能になるまで

まず元アイテムと登録名を決め、既存品質 ID をバインドするか、食用可能か、スタック/リソースオプションを選択します。保存後、同じ登録リストと必要なクライアントリソースを配布し、サーバーとクライアントの登録手順に従って再起動します。/hdreload は有効待ちリストを再読み込みできますが、新規 ID を稼働中のワールドに挿入することはできません。

マルチサーバー：新規登録 ID を追加する場合、サーバーとクライアントは一致した登録定義とリソースを持つ必要があります。サーバー側のホットリロードだけで、まだ登録されていない新アイテムをオンラインプレイヤーに配布しないでください。先に配布を完了し、登録手順に従って再起動してください。
ソース根拠：QualityRegistryEntry、ConfigManager 登録計画、HDReloadCommand。
