01カラースキームと単色パレット

グラデーションスキームは colors/color_schemes.json で ID により参照します。単色パレットは colors/solid_colors.json で選択可能な色を定義します。

たとえば栄養グループの配色はグラデーションスキームを参照できます。品質やツールチップ行もスキームを設定するか、単色を直接使用できます。カラーテーブルが提供するのは色のソースであり、あるツールチップ行を表示するかどうかを決めるものではありません。

色見本の例A → B
例の色は現在の内蔵配色の1つのスキームから取得しています。Web の色バーはゲームのスクリーンショットではなく、各栄養グループの実際の色を示すものでもありません。
ソース根拠：ConfigManager の配色ファイルパス、デフォルトスキーム、RarityConfig.scheme。

02静的グラデーションと動的スタイル

静的テキストは文字ごとにグラデーション色を割り当てられ、時間経過で変化しません。動的効果が必要なときだけ対応スイッチを有効にします。
動的現在 gradient、breathing、wave、pulse などのスタイルをサポートします。速度、ステップ数、一部の固有パラメータを個別に設定します。

波とパルスにはそれぞれのステップ幅または遅延があります。色順の反転とアニメーション方向の反転も独立した2つの設定です。ツールチップ行は複数のテキストセグメントで構成でき、各セグメントが独自の配色とアニメーションパラメータを持ちます。

パラメータの組み合わせ

dynamic=false のときは文字ごとに静的グラデーションを表示します。動的を有効にすると、nameStyle でアニメーションを選び、speed でループ周期（ミリ秒）、steps でカラーテーブルのサンプリング精度を制御します。waveStep は波紋だけ、pulseDelay はパルスの文字ごとの伝播だけに影響します。セグメントテキストを使う場合、各セグメントは独立した配色とアニメーションを持ち、トップレベルのテキストとグラデーションパラメータはセグメント設定を上書きしません。

ソース根拠：TooltipLineConfig の dynamic、nameStyle、segments、colorReverse、dynamicReverse。

03色を適用する場所

  • 1アイテム名とツールチップ追加行：テキスト、グラデーション、セグメント、動的スタイル、表示条件を設定できます。名前行と追加行では制限が異なります。
  • 2品質とレアリティ：品質にはオーバーレイ、セグメント品質テキストを設定できます。レアリティはレアリティ表示と関連するアイテム名の色に影響します。
  • 3食べ飽き情報：fatigue/fatigue_gradient.json で食べ飽き関連のツールチップ色を管理します。
  • 4保存期間状態：shelf_life/schemes/ の保存期間表示スキームを使用し、共通グラデーションパレットとは区別されます。

色を変更する前に対象行のソースを確認してください。栄養グループ色、アイテム名、自作行は1つの「グローバルテキスト色」スイッチを共有していません。品質テキストは品質定義から参照され、レアリティはアイテムと NBT バリアントごとに上書きできます。共通グラデーションスキームを変更すると、それを参照するすべての場所に影響します。1種類のツールチップだけを変えたい場合は、その種類のバインディングまたは個別スキームを編集してください。

アイテム名の配色を複製：/hdset tooltip <ソースアイテムID> hand|<ターゲットアイテムID> (OP2) は、ソースのアイテムレベル共通エントリ先頭行の配色スキームと動的フィールドをメインハンドのターゲットまたは明示的なアイテム ID にコピーします。先頭行のテキスト、星マーク、他の行、NBT バリアントはコピーしません。ソースまたはターゲットの先頭行がセグメントテキストの場合は拒否され、セグメント配色を直接複製できません。セグメントごとに編集するには ツールチップ編集入口 から操作してください。
ソース根拠：HDSetCommand.buildTooltipNode/doTooltipCopy、QualityLevelConfig、TooltipLineConfig。

04サーバー側ルールとクライアント表示

サーバー管理者はルール的な内容を維持し、オンラインプレイヤーに同期できます。たとえば食べ物ツールチップのレイアウト、品質定義、保存期間表示スキームです。クライアントローカルの表示設定と一部のローカル配色ファイルは、サーバー側で /hdreload を実行しても自動的にリモート再読み込みされません。

そのため、外観を変更する前に、設定ファイルがサーバーから配信されるものか、各クライアントが自分でインストール・リロード・ワールド再入場する必要があるものかを区別してください。登録品質アイテムのカスタムテクスチャについては、クライアントに対応リソースも必要です。

「サーバー管理者が変更したのに自分は変わらない」の調査

対象がアイテム/品質などのサーバー定義にあるのか、プレイヤーのクライアントローカル配色にしかないのかを確認し、クライアントがテクスチャやフォントリソースを持っているかも確認します。/hdreload は同期可能なサーバー側ルールを再読み込みして配信しますが、プレイヤーのローカルファイルを書き換えるわけではありません。Web の色見本もサーバーデータに自動追従しません。

パス移行：旧版の rarity_and_colors/ と shelf_env/ ディレクトリは現在の編集パスではありません。実際のインストールディレクトリの colors/、fatigue/、shelf_life/ を確認してください。
ツールチップ行の表示方法？通常、S、D モードを確認してから、どの行にどの配色を適用するか決めてください。
