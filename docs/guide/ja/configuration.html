設定リファレンス：ファイルとゲーム内 UI

各サーバー/クライアントファイルの場所、フィールドの既定値、設定画面の読み取り専用イメージ、更新ルールを確認できます。

既定値とプレビュー：「既定」は新しいファイルまたはコードの初期値であり、サーバーの現在値ではありません。HTML UI は読み取り専用で、接続・保存・ライブデータ表示は行いません。_note_* フィールドは説明専用です。

01ファイル、所有者、更新

特に断らない限り、パスは config/healthy_diet/ からの相対パスです。データパック項目は data/<名前空間>/healthy_diet/ にあります。ファイル、スコープ、フィールドでフィルタできます。

ファイル / ディレクトリスコープ役割一般的な更新方法
server.jsonサーバー権威ゲームルール、プライバシー、保存期間スタック統合、テストログOP ゲームプレイ画面または /hdreload
display.jsonローカルクライアントツールチップレイアウト、温度単位、既定表示モードクライアント画面で保存。手動編集後はクライアント再起動
colors/color_schemes.json両側 / 外観グループ、品質、ツールチップ、スキームが参照する名前付きグラデーションサーバーで /hdreload。ローカルクライアントファイルは別途再読み込み
colors/solid_colors.json両側 / 外観エディターのカラーピッカー用パレットサーバーで /hdreload。クライアントローカルは別途更新
fatigue/fatigue_gradient.json外観食べ飽き/回復行の色とアニメーション/hdreload
fatigue/fatigue_exempt.jsonサーバーゲームプレイ他の食べ物による回復カウントから除外するアイテム ID/hdreload
shelf_life/seasons.jsonサーバーゲームプレイ季節ごとの腐敗倍率。Ecliptic Seasons なし時のフォールバック/hdreload
shelf_life/schemes/*.json同期表示保存期間テンプレート、色、季節名/hdreload とクライアントへのスキーム送信
temperature/block_heat.jsonサーバーゲームプレイLSO ワールド温度分岐を使わない場合のブロック熱ルール/hdreload または温度画面の保存
temperature/weather_offsets.jsonサーバーゲームプレイ24節気ごとの雨/雪・雷のオフセット/hdreload または温度画面の保存
temperature/day_night_offsets.jsonサーバーゲームプレイ24節気ごとの正午/深夜オフセット/hdreload または温度画面の保存
temperature/season_temperature.jsonサーバーゲームプレイ節気ごとの追加環境温度オフセット（EC 気候の上に加算）/hdreload または温度画面の保存
bottle_fills.jsonサーバーゲームプレイ液体水源への右クリック消費と出力/hdreload
fog_effects.jsonローカルクライアント設定効果に応じた水中/溶岩の霧距離ローカルクライアントファイルを再読み込み。サーバーリロードではない
item_rarities.jsonサーバー / 同期アイテムレベルのフォールバックレアリティ ID/hdreload。/hdset rarity も更新する
tooltip_templates.jsonエディターローカルローカルツールチップ行テンプレートエディターがローカルインスタンスを読み書き。グローバルクライアント同期ではない
quality_registry/*.json起動時登録新しいアイテム ID、ソース、モデル、品質、食用動作、スタック上限ID の追加/削除は両側を再起動
datapack/data/<ns>/healthy_diet/ワールドデータパック + HD オーバーレイitems / tooltips / blocks / nutrition_* / quality_levels / rarities / effect_linesワールドパックはバニラ /reload、HD オーバーレイは /hdreload
設定 JSON、ワールド/HD データパック、起動時レジストリ項目はライフサイクルが異なります。データパックファイルを旧 config/healthy_diet/items/ にコピーしても、現在のアイテム定義にはなりません。

02server.json：サーバー権威セクション

1つのファイルに gameplay、privacy、shelfMerge の3セクションがあります。旧来の別ファイルはこのファイルへ移行され、migration_backup/ に移動します。

フィールド新規ファイルの既定値動作
shelfTemperatureEnabledfalse保存期間と温度のマスタースイッチ。オフ時は劣化、温度/鮮度、期限切れ産物とコマンド、温度拒否、温度帯効果、関連ツールチップ行を停止します。既存アイテムデータは保持され、停止期間は遡って加算されません。
lsoIntegrationEnabledtruehd:shelf が LSO ワールド環境全体を読むことを許可します。他の LSO 互換機能は無効にしません。
ecIntegrationEnabledtrueEC 気候と HD 季節腐敗倍率の直接利用を許可します。LSO が既に提供する EC データは変更しません。
proxyHeatstrokeEffecttrueサーバーが5秒ごとに確認し、LSO の熱中症を EC の熱中症へミラーしてぼかし効果を出します。ソースがない、または免疫がある場合は削除します。
bonusUpdateTicks100属性ボーナスの更新間隔（1–1,728,000 tick、既定約5秒）。
effectUpdateTicks200ポーションボーナスの更新間隔（1–1,728,000 tick、既定約10秒）。
ejectIllegalProtectedItemsfalse未信頼の所持者が保護アイテムを持つ場合、true は足元にドロップし、false はその場で凍結して警告します。既定は誤分類によるアイテム喪失を避けます。
removeOwnerOnDeathDropfalsetrue はすべての死亡ドロップの保護を解除します。false は元々持ち主のないドロップだけに死亡者 UUID を設定し、既存の持ち主を保持します。
debugLogsfalseブロック右クリックと設置/分割食品のサーバー診断ログ。/hdreload で再読み込みし、調査後に無効化してください。
privacy.sendCommandTextToAllPlayersfalse既定では OP4 だけがステージコマンドテキストを受け取ります。true は実行権限を変えずに全ステージ設定を非 OP プレイヤーへ送ります。
shelfMerge.mergeRemainingMinutes5スタックを許可する残り時間差の最大値（1–1,440分）。
shelfMerge.mergeTempThreshold10.0スタックを許可するアイテム温度差の最大値（0–100℃）。NaN 差は無視されます。
shelfMerge.mergeColdFreshThreshold20.0スタックを許可する冷鮮度差の最大値（0–100）。
ゲーム内 OP サーバー画面が保存するのは gameplay のみです。privacy と shelfMerge はディスク上で編集してから /hdreload してください。読み取り専用ファイルの場合、保存は失敗し、メモリ上の権威値は変わりません。

03display.json：クライアントローカル設定

ローカル外観と編集既定値はサーバーゲームプレイ同期の対象ではありません。サーバールールは server.json → gameplay にあります。

フィールド新規ファイルの既定値動作
nutritionPerLine6通常ツールチップの栄養/条件項目の最大数。超えると省略記号で切り捨て。1は最初の項目だけを意味し、1行1項目ではありません（1–100）。
titleproWrapWidth1000TitlePro タイトルの折り返し幅（ピクセル、1–100,000）。
defaultConditionalGainEnabledtrue新規条件ルール草稿の「実際の増加」既定選択。保存済みルールの実行時スイッチではありません。
infoGapWidth20D モードで左テキストと右寄せ内容の間の固定余白（0–100,000）。
maxInfoWidth320D 情報パネルの最大幅。S 詳細表示はこの制限を受けません（0–100,000）。
showUnifiedPotionStylefalseポーションスタイルのマスタースイッチ。false はアイテムと既定の強制統一選択をバイパスします。
enableEnchantmentInfotrue翻訳キーがある場合、D モードでエンチャント本の説明を自動表示します。
enablePotionInfotrueD モードのバニラ/HD/外部効果、統一属性、LSO 渇き情報ブロックを制御します。通常のコンパクト効果、温度帯効果、JEI/カスタム D テキスト、エンチャント説明は残ります。
hideSystemPrefixesfalseHD が生成する行頭記号と余白だけを隠します。カスタム名、インライン区切り、セグメントテキストは隠しません。
temperatureUnitcelsiusこのクライアントのツールチップ/HUD 用に celsius または fahrenheit。保存設定とエディターは摂氏のまま。無効値は摂氏へフォールバック。
temperatureUnitChosenfalseこのクライアントが温度単位を明示選択したか。ローカル初回プロンプト状態。
groupLocalizePromptedfalse内蔵グループ名翻訳に関するローカル OP プロンプト状態。共有設定ではありません。
defaultEffectsShiftOnlyfalse新規ポーション行の既定表示：常時 vs Shift のみ。既存行は各自の選択を保持します。
defaultForceUnifyfalse新規効果行の強制統一初期選択。アイテムに既にツールチップ設定/データパック項目がある場合のみ適用。
defaultFoodBarDisplayModealwaysalways / shift / info / off。off はバニラの食料値行へフォールバック。未設定アイテムと新規行に影響します。

廃止されたパネルオフセット/幅とテキストシャドウフィールドはこのファイルに含まれません。_note_* は読み取り専用ヘルプです。クライアント画面で保存すると即時反映され、手動編集後はそのクライアントを再起動してください。

04栄養データパック：グループ、ステージ、ボーナス

data/<名前空間>/healthy_diet/ 配下は nutrition_groups/<groupId>.json（グループ定義1件）、nutrition_stages/<groupId>.json（ステージ + hideAutoBonus）、nutrition_bonuses/<groupId>.json（メモ + ボーナス）です。HD オーバーレイは config/healthy_diet/datapack/ に置き、ファイル名はグループ ID です。最大64グループ。

グループフィールド

フィールド既定値説明
displayNameGroupUI/ツールチップに表示するグループ名。内蔵既定にはローカライズ名があります。
nutritionSymbolΨ 栄養行の接頭辞。空欄は既定値 + スペースへフォールバック。
order0昇順の表示順。同値はグループ ID で決まります。
color / colorStyle#FFFFFF / null16進単色またはスキームキー。style はスキームの dynamic/nameStyle/speed/steps/waveStep/pulseDelay/reversals/bold/italic/underlined を制御し、単色では無視されます。
decayRate6.0消費した満腹度1ポイントごとに栄養を 1/decayRate 減らします。0以下は自然減少を無効化。
iconempty任意のアイテムアイコンリソース。空欄は UI フォールバック。
initialValue0新規プレイヤーまたは新規追加グループの初期値、0–100。
gainMultiplier1食べ物の正負変化に掛けます。0 可。負/非有限値は1へフォールバック。最終値は0–100にクランプ。
enabledtrue無効化すると全プレイヤーで非表示/凍結し、減少、条件、ボーナスを停止します。
requiredPlayerTagempty必要なプレイヤースコアボードタグ（完全一致）。空欄は制限なし。アイテム/ブロックタグではありません。
requiredModIdempty必要なロード済みサーバー MOD ID。空欄は制限なし。
nutritionTipColorsgenerated4スロット：通常/条件 × 増加/減少。カスタマイズは増加がグループ名色に従うかを制御します。

ステージとボーナスフィールド

フィールド既定値説明
stages[].min/max0/100両端を含む整数境界。判定前に現在値を四捨五入。隣接ステージは重複も空白も不可。
stages[].label/tooltip/commandsempty / [] / []任意のタイトル、追加ホバー行、設定済みステージコマンド。コマンドテキストは privacy が許可しない限り OP4 にだけ送信されます。
hideAutoBonusfalsetrue の場合、このグループの全ステージツールチップで自動範囲タイトルとボーナスプレビューを抑制します。
remarkemptyエディター一覧のラベル。空欄はファイル名。計算には影響しません。
bonuses[].conditions{}グループ ID → {min,max}。複数条件は AND。
bonuses[].attributeBonuses[][]attribute（既定 max_health）、operation add/multiply_base/multiply_total（既定 add）、value。
bonuses[].effectBonuses[][]effect ID、level（0=I）、duration tick（既定200）、showParticles（既定 false）。
例のグループは displayName「Fruit」、nutritionSymbol「Ψ 」、decayRate 6、gainMultiplier 1、カラースキームキー「a」を使えます。これは例のファイルであり、すべてのグループが同じスキームを使う必須要件ではありません。

05アイテム、ツールチップ、ブロック、品質

データパックディレクトリ：items/<itemPath>.json、tooltips/<itemPath>.json、blocks/<blockPath>.json、quality_levels/<id>.json、rarities/<id>.json、effect_lines/<effectId>.json。アイテム/ツールチップ項目は .json.disabled に対応し、ブロックは非対応です。効果行スタイルは、そのポーション行が強制統一を選択した場合のみアイテムを上書きします。

アイテムフィールドグループ

フィールド意味
nutritionグループ ID → 食べ物変化。グループ取得倍率、生涯係数、摂取分割数が掛かります。
effects摂取後ポーション設定：レベル、tick 時間、確率、粒子、任意の鮮度曲線。
foodCooldown短期 maxUses、cooldownCount、cooldownMinutes、restoreHunger。
foodFatigue生涯 lossStart と aversionCount。両方設定時のみ線形減少。
shelf基本時間、温度曲線、ディメンション倍率、冷鮮/保冷、環境温度、摂取効果。
onEatCommands / suppressEffects摂取コマンドとアイテム固有効果の削除。それぞれ独自の遅延があります。
conditionalRules栄養条件 → 対象変化、コマンド、ヒント。ルール全体として保存。
stackSizeアイテムレベルの最大スタック。0 = バニラ。再起動が必要で、NBT バリアント別の上限はありません。
quality / rarity品質/レアリティ ID をバインド。レアリティは variant → generic → item_rarities.json → バニラの順に解決。
nbtLock / variantNameNBT マッチングと注記。空の nbtLock は汎用アイテム項目を意味します。

ブロック操作フィールド

フィールド既定値意味
state{}ブロック状態プロパティのサブセット。空は任意に一致。より具体的な状態が優先。
hand / itemsany / []any、空のメインハンド、または hand=item 時にアイテム ID/#タグへ一致するアイテム。

sneakanyany、スニーク要求、スニーク禁止。
cooldownTicks20バリアントごとのクールダウン、0–72,000 tick。0 はクールダウンを書きません。
cancelVanillafalse一致時にバニラ操作をキャンセル。長押し操作の重複排除に影響。

06保存期間と温度フィールド

アイテムごとの shelf 値は shelf_life/ と temperature/ の季節/環境ファイルとは異なります。既定値は新規作成設定に適用され、内蔵食品が上書きすることがあります。

フィールド既定値説明
durationMinutes / durationUnit60 / minutes基本分 1–99,999。エディター単位は分、時間、実日（1,440分）、game_days（20分）。無効単位は分へフォールバック。
resultItem / inheritTemperatureOnExpireminecraft:air / trueair は消滅。他の結果は温度だけを継承し、以前の保存期間進行は継承しません。
expireCommandempty所持者の手元で期限切れになったとき、所持者コンテキストで実行。コンテナ内やドロップ品の期限切れでは実行しません。
baseDecayMultiplier1.0非負の基本腐敗倍率。
temperatureCurves[]最大16本の温度→劣化曲線。線形端点と任意の外側バッファ。
dimensionDecayMultipliers{}ディメンション ID → 倍率。未記載は ×1。
schemehd:shelf_en表示スキーム ID。旧 hd:shelf は現在のスキームへ正規化。
coldRetention / coldRecoveryRate / coldDegradationRatefalse / 1 / 15完全凍結時の回充を有効化。1分あたり回充分 0–100。基本時間の1–100%消費ごとの永久回充上限低下。
temperatureEffectCurves[]最大20件の摂取時温度帯効果。劣化曲線とは独立。
common.minTemperatureC / maxTemperatureC / initialTemperatureC-30 / 100 / 10アイテムの絶対境界と初期温度。内蔵食品が上書き可能。
common.eatableMinTemperatureC / eatableMaxTemperatureC-5 / 35この摂氏範囲外では食べられません。
common.coldFreshStartC / freezingStartC / fullyFrozenC3 / -5 / -20冷鮮進行と凍結しきい値。
common.highTemperatureC / preservationRate30 / 0.8高温帯開始と冷鮮50%時の腐敗保護。
naturalEnvironment.temperatureChangeC / temperatureChangeMinutes1 / 2環境基準：既定では2分ごとに1℃。
naturalEnvironment.lowSpeed* / highSpeed*separate降温/昇温の速度ステップ増分、温度差、倍率上限。
naturalEnvironment.*SpeedMultiplierBonus0冷凍/低温/常温/高温帯の追加温度変化速度。
fridgeTemperature.*ChangeC / *Minutesfridge 5/2; freezer 10/2冷蔵庫/冷凍庫の基本温度変化速度。
fridgeTemperature.*SpeedMultiplierBonus0冷蔵庫内の4温度帯追加変化速度。
temperatureZoneEffectsnull旧4スロット移行入力。temperatureEffectCurves へ正規化。新規項目には使わないでください。

曲線と効果の端点

配列フィールド / 制約
temperatureCurves[]startTemperatureC < endTemperatureC。端点倍率 0–100。任意の startBufferTemperatureC / endBufferTemperatureC。区間/バッファ外では ×1。旧 startBufferC/endBufferC は読み取り専用移行。
temperatureEffectCurves[]effectId、絶対摂氏 start/end、includeStart/includeEnd（既定 true）、start/end level 0–127（0 = I）、start/end duration 1–72,000 tick（20 tick = 1秒）、particles 既定 true。旧4区移行は有効な単一点範囲を作ることがあります。

季節と環境ファイル

パス用途
shelf_life/seasons.jsonfallbackMultipliers.shelfLifeMultiplier は EC なしで既定 ×1。seasons[] は ID、節気範囲 0–23、倍率 0–100、表示名。旧6季節ファイルも引き続き対応。
temperature/season_temperature.jsonterms[]：節気 0–23 と環境オフセット −100–100℃。EC 気候に加算。
temperature/weather_offsets.jsonterms[]：雨 −1、雷 −2 が既定。降水なしはオフセットなし。
temperature/day_night_offsets.jsonterms[]：正午/深夜の既定 0。日内と節気間で滑らかに補間。
temperature/block_heat.jsonentries[] の block + rules[] 温度 −1000–1000 と状態プロパティ。非 LSO 分岐で最初に完全一致したルールが優先。

07外観スキームと小ツール

ファイル構造と制限
colors/color_schemes.jsonスキーム ID → {colors:[#RRGGBB,...]}。2色以上で可視グラデーション。共有スキームの編集はすべての参照に影響。
colors/solid_colors.json#RRGGBB ピッカースウォッチの配列。無効値は無視。
fatigue/fatigue_gradient.jsonenableGradient、fatigueLevelGradient、fatigueRecoveryGradient。scheme、stars、dynamic style、speed/steps/wave/pulse/reversals。表示のみを変更し、クールダウンしきい値は変えません。

08ゲーム内設定 UI 図解

設定メニュー（/hdconfig）

/hdconfig はクライアントローカルコマンドで、実行自体が OP4 を確認します。非 OP プレイヤーは他のゲーム画面からローカル外観設定へ入れますが、このコマンドを直接実行することはできません。ページのモックアップは読み取り専用で、実値は取得しません。

クライアント外観 · 12の編集可能行

サーバーゲームプレイ · 9項目とリセット操作

温度連動 · 5テーブル + 別個の LSO 項目

5つのサーバーテーブルタブは1つの草稿と1回の検証済み保存を共有し、タブを切り替えても未保存変更は保持されます。6番目は独立フォームを開きます。以下のタブはファイルグループの説明のみで、データは変更できません。

腐敗倍率

季節 ID ごとの倍率 0–100。既定 ×1。有効な EC 節気と EC 連動有効が必要。旧6季節ファイルは6項目のまま。

ブロック熱

ブロック名または ID で検索。+ は加熱、− は冷却、−1000–1000。状態ごとに別ルールを持て、熱、距離、遮蔽が実際の寄与を決めます。

昼夜

節気ごとの正午/深夜オフセット、各 −100–100℃（既定0）。日中に補間され、バイオーム固有端点が優先。

季節温度

EC 気候の上に節気ごとの追加 −100–100℃（既定0）。EC なしでは最初の節気を使用。

雨/雪

雨/雪の既定 −1℃、雷雨の既定 −2℃、各節気 −100–100℃。雷は通常の雨値を加算しません。

LSO ワールド温度

別個のディメンションフォームで、5テーブル共同保存には含まれません。ワールド温度値は LSO 単位で、摂氏ではありません。

節気順：立春、雨水、啓蟄、春分、清明、穀雨、立夏、小満、芒種、夏至、小暑、大暑、立秋、処暑、白露、秋分、寒露、霜降、立冬、小雪、大雪、冬至、小寒、大寒。プレビューはサーバーの実際の24項目を読み込みません。
