03 / QUALITY & RARITY

품질, 희귀도, 독립 아이템을 각각 설정하기.

품질은 추가 품질 표시를 결정하고 희귀도는 아이템 희귀도 표시를 바꿉니다. 품질 아이템을 등록하면 새로운 아이템 ID가 생성됩니다. 세 가지는 같은 설정이 아닙니다.

품질 바인딩희귀도 덮어쓰기독립 아이템 ID
중요한 구분: 기존 아이템의 품질/희귀도를 수정하는 것은 새 아이템을 등록하는 것과 다릅니다. 독립 등록 아이템의 추가/삭제는 시작 시 등록과 관련됩니다. 핫 리로드 정의와 신규 아이템 등록을 혼동하지 마세요.

이 페이지 목차

  1. 기능 비교
  2. 품질 정의
  3. 희귀도 덮어쓰기
  4. 품질 아이템 등록

01세 기능의 차이

품질문자열 ID로 품질 텍스트, 세그먼트 스타일, 선택적 오버레이를 정의합니다. 기존 아이템은 quality 필드로 바인딩할 수 있습니다.
희귀도아이템 이름과 희귀도 표시에 사용합니다. 사용자 지정 희귀도 또는 바닐라 희귀도를 선택할 수 있습니다. 새 아이템 ID를 만들지 않습니다.
등록 아이템원본 아이템을 기반으로 독립 ID를 등록하고 품질, 이름, 모델, 섭취 속성, 스택 한도를 지정할 수 있습니다.
소스 근거: ItemConfig.quality, ItemConfig.rarity, QualityRegistryEntry.

02품질 정의와 바인딩

품질 ID는 문자열이며 기존 숫자 레벨이 아닙니다. 유효한 ID는 1–64자의 소문자 영문, 숫자, _, -, .입니다.

각 품질 정의는 데이터팩 data/<네임스페이스>/healthy_diet/quality_levels/<id>.json에서 읽습니다. 텍스트, 색상 또는 색상 스킴, 세그먼트 텍스트, 오버레이 텍스처를 설정할 수 있습니다. 정의한 ID는 기존 아이템의 '품질 바인딩'에서 선택할 수 있고 신규 등록 아이템에서 참조할 수도 있습니다.

설정 경로 예시

config/healthy_diet/datapack/data/healthy_diet/healthy_diet/quality_levels/fresh.json

여기서 fresh는 유효한 파일 이름 예시이며 반드시 존재하는 기본 품질은 아닙니다.

/hdui create를 열면 품질 정의를 관리할 수 있습니다. 아이템을 들고 /hdui를 열면 해당 아이템에 품질을 바인딩할 수 있습니다. 정의 변경은 새로고침 및 동기화할 수 있지만 오버레이가 보이는지는 클라이언트 리소스와 사용하는 표시 컴포넌트에 따라 달라집니다.

화면 근거: HdCreateScreen.buildQualityForm/qualityErrors. 이 페이지 라벨은 현재 zh_cn을 참조합니다.
작업 순서

먼저 품질 ID를 만들거나 확인하고 기존 아이템에 quality 참조를 설정합니다. 정의를 만드는 것만으로 모든 음식에 품질이 자동 부여되지 않습니다. 존재하지 않는 ID를 입력해도 해당 텍스트나 텍스처가 저절로 생성되지 않습니다. 이미 해당 ID를 바인딩한 아이템은 업데이트된 품질 정의를 사용합니다.

소스 근거: QualityLevelConfig.ID_PATTERN, segments, overlay, HdCreateScreen.

03희귀도: 아이템에 희귀 등급 지정

희귀도에는 텍스트, 색상, 애니메이션을 설정할 수 있습니다. 아이템 바인딩은 /hdset rarity <희귀도id> [아이템ID] (OP2) 또는 아이템 편집기에서 합니다. 덮어쓰기 해제는 /hdset rarity clear [아이템ID] (OP2)입니다. 명시적 아이템 ID가 없으면 주 손에서 일치하는 NBT 변형이 대상이 되고 ID가 있으면 아이템 레벨 폴백을 조작합니다.

/hdui create (OP4)의 '희귀도' 탭에서는 희귀도 정의를 관리합니다. ID는 1–64자의 소문자 영문, 숫자, _만 사용할 수 있습니다. 세그먼트 텍스트를 편집한 뒤 새로 만들기, 수정, 삭제가 가능하고 상태를 확인할 수 있습니다. 유효한 신규 희귀도 정의는 프록시 열거로 즉시 반영 및 동기화됩니다. 과거의 '재시작 대기' 표시를 모든 희귀도에 공통된 조건으로 생각하지 마세요. 정의가 유효하지 않으면 텍스트와 색상을 확인해야 합니다.

화면 근거: HdCreateScreen.buildRarityForm/rarityErrors, CPacketCreateEntry.RARITY_ID_PATTERN, 현재 zh_cn 라벨.
같은 아이템의 다른 변형에 색상 지정

먼저 아이템에 공통 희귀도를 설정하고 필요에 따라 특정 NBT 변형에 개별 지정합니다. 해당 변형에 일치하는 아이템만 변형 덮어쓰기를 사용하고 나머지는 공통 희귀도를 사용합니다. 일치하는 변형의 희귀도를 해제하려면 해당 변형을 들고 ID 없는 /hdset rarity clear를 실행합니다. 아이템 ID가 있는 명령어는 item_rarities.json의 아이템 레벨 폴백을 해제합니다. 해제 후에도 다음 계층 소스를 확인해야 하며 '덮어쓰기 해제'가 흰색 이름을 보장하지 않습니다.

  • 1일치하는 NBT 변형이 우선합니다. 설정되지 않았으면 공통 항목, 아이템 레벨 item_rarities.json, 마지막으로 아이템 원래 희귀도 순으로 폴백합니다.
  • 2신규 희귀도 정의는 프록시 희귀도로 표시 및 핫 업데이트할 수 있으므로 화면의 과거 '재시작 필요' 표시를 모든 희귀도의 실제 요구 사항으로 보지 마세요.
  • 3희귀도 변경은 희귀 등급과 아이템 외형에만 영향을 주며 새로운 품질 등록 아이템을 저절로 생성하지 않습니다.
소스 근거: ItemConfig.rarity, RarityManager.DATAPACK_PROXY_ID, HDSetCommand.

04독립 등록 아이템

/hdui registry (OP4)로 품질 레지스트리 관리자를 열어 등록 항목을 보기, 새로고침, 삭제할 수 있습니다. /hdui create의 세 탭은 새 아이템 등록을 담당하지 않습니다. 각 등록 정의는 원본 아이템을 가리키며 등록 이름, 품질 ID, 섭취 또는 음용 동작, 스택 수 등을 설정합니다.

기존 아이템 바인딩과 달리 등록 항목은 새로운 healthy_diet 아이템 ID를 생성합니다. 아이템 등록은 시작 단계에서 이루어집니다. 정의는 로컬 config/healthy_diet/quality_registry/*.json에 저장됩니다. 관리자가 수정하는 것은 다음 시작 시 적용될 계획이며 /hdreload로 완전히 새로운 ID를 현재 아이템 레지스트리에 즉시 추가할 수는 없습니다.

정의에서 배포 가능 상태까지

먼저 원본 아이템과 등록 이름을 정하고 기존 품질 ID를 바인딩할지, 섭취 가능 여부, 스택/리소스 옵션을 선택합니다. 저장 후 같은 등록 목록과 필요한 클라이언트 리소스를 배포하고 서버와 클라이언트의 등록 절차에 따라 재시작합니다. /hdreload는 적용 대기 목록을 다시 읽을 수 있지만 새 ID를 실행 중인 월드에 삽입하지는 않습니다.

멀티 서버: 새 등록 ID를 추가할 때 서버와 클라이언트는 일치하는 등록 정의와 리소스를 가져야 합니다. 서버 측 핫 리로드만으로 아직 등록되지 않은 새 아이템을 온라인 플레이어에게 배포하지 마세요. 먼저 배포를 완료하고 등록 절차에 따라 재시작하세요.
소스 근거: QualityRegistryEntry, ConfigManager 등록 계획, HDReloadCommand.
관련 내용품질 줄, 희귀도 표시, 그라데이션 스킴은 표시 장에서 계속 설명합니다.
