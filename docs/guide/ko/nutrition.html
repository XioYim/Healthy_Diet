01메커니즘 개요

각 영양 그룹은 독립된 0–100 수치 축입니다. 음식은 여러 그룹에 동시에 영향을 줄 수 있고 허기가 줄면 각 그룹이 설정된 감소율로 줄어듭니다.

같은 음식이라도 그룹별 기여도는 다릅니다. 예를 들어 사과는 과일과 당분을 동시에 늘립니다. 음식 간의 차이가 식생활 구조를 만듭니다.

영양 패널 예시

H를 누르면 영양 패널이 열립니다. 그룹 이름, 색상, 단계 범위는 Forge 메인라인 내장 JSON에서 가져옵니다. 각 단계에 호버하거나 키보드 포커스를 두면 실제 설정된 보너스 미리보기를 확인할 수 있습니다. 기본 단계에는 직접 작성한 이름이나 설명이 없어 툴팁에는 범위, 설정된 보너스, 필요한 클릭 명령어 안내만 표시됩니다.

영양 상태 · 설정 예시H로 열기
HTML 모의 화면이며 게임 스크린샷이 아닙니다. 6개 색상 블록은 아이템 아이콘을 대신하지 않습니다. 표시 값은 예시 플레이어 상태이며 기본 초기값이 아닙니다. 단계 구역에 마우스를 올리거나 Tab으로 포커스하면 해당 구간의 실제 기본 보너스를 확인할 수 있습니다. '확인 완료'에 호버하면 이 예시 값에서 현재 활성화된 보너스를 확인할 수 있습니다. 여기서 게임 명령어가 실제 실행되지는 않습니다.
설정 소스: nutrition_groups.json과 기본 데이터팩의 nutrition_stages/*.json, nutrition_bonuses/*.json. 색상은 color_schemes.json에서 가져옵니다. 예를 들어 기본 채소 그룹은 initialValue가 42, decayRate가 6입니다. 그림의 55%는 46–60 구간의 보너스를 보여 주기 위한 예시입니다. 보너스 툴팁은 HealthyDietScreen과 BonusTooltipUtil에 기반하며 임의 설명을 기본 설정에 기록하는 것이 아닙니다.
수치 체계: 허기와 영양 수치는 서로 독립적입니다. 허기는 배고픔과 섭취에, 영양 수치는 장기 식생활 구조에 사용합니다.

02증가와 감소

섭취에 의한 증가와 허기에 의한 감소는 두 개의 독립된 계산 경로입니다.

섭취 증가량은 대략 음식 기본값 × 해당 그룹 획득 배율입니다. 평생 거부감이 있으면 감소 계수를 추가로 곱합니다. 계산 후 0–100으로 클램프됩니다. 관리자 명령어, 자연 감소, 초기값은 획득 배율을 거치지 않습니다.

슬라이더는 감소 공식 데모입니다. 계산은 100에서 시작하며 실제 초기값을 나타내지 않습니다.
  • 1범위는 항상 0–100. 영양 수치는 소수를 유지할 수 있고 계산 후 상하한으로 클램프됩니다.
  • 2단계 판정은 정수. 현재 값을 반올림한 뒤 단계에 일치시킵니다. 예를 들어 59.6은 60으로 처리합니다.
  • 3사망해도 영양 수치는 사라지지 않습니다. 리스폰 시 데이터가 플레이어 능력으로 복사됩니다.
예시와 설정: 감소율, 초기값, 획득 배율은 서버가 조정할 수 있습니다. 실제 값은 /headiet 패널과 서버 설정을 따릅니다.

03단계

단계는 영양 수치 구간과 관련 동작입니다. 단계 제목, 설명, 클릭 명령어는 단계 페이지에서 편집하고 그룹 교차 지속 효과와 속성 보너스는 독립 효과 페이지에서 구간 조건별로 설정합니다.

단계 경계는 정수를 사용합니다. 편집기는 인접 구간을 검증해 값이 단계 사이 빈틈에 들어가지 않도록 합니다. 판정 시 먼저 반올림한 뒤 구간에 일치시킵니다.

낮음 0–29
중간 30–69
높음 70–100
정수 판정: 60 현재 예시 단계: 중간
단계 이름과 0–29 / 30–69 / 70–100은 예시입니다. 서버는 더 많은 단계나 다른 경계를 설정할 수 있습니다.

단계 설정 항목

이름과 설명 단계를 식별하고 현재 상태를 설명합니다. 설명은 영양 패널 툴팁에 표시됩니다.
클릭 명령어 플레이어가 단계를 클릭할 때 실행합니다. 관리자 권한으로 동작하고 출력은 억제됩니다.
자동 보너스 미리보기 단계에 설정된 속성과 효과를 툴팁에 자동 추가합니다. 중복 표시를 피하려면 끌 수 있습니다.
클릭 쿨다운: 단계 명령어는 같은 플레이어에서 1.5초 간격이 필요하고 서버가 다시 검증합니다. 명령어는 서버 관리자가 설정합니다. 출처가 불분명한 단계 명령어를 클릭하지 마세요.

게임 내 /hdui stage: 단계／명령어／설명

OP4가 필요합니다. 왼쪽에는 활성화된 영양 그룹만 표시됩니다. 아래 세 그림은 각각 하나의 Tab 구조를 보여 줍니다. 그림 안의 탭 링크는 해당 그림으로 이동할 수 있습니다. 그림 안의 버튼과 입력란은 읽기 전용 예시이며 게임 설정을 저장할 수 없습니다.

화면 근거: StageManageScreen.buildContentTabs/buildEffectButton/buildStageBottomButtons, buildCommandRows/buildDescriptionRows, 현재 zh_cn 라벨.

04보너스와 연동

독립 효과 페이지에서는 하나 이상의 영양 그룹 구간 조합에 지속 속성 수정자와 물약 효과를 설정할 수 있습니다. 모든 조건을 만족하면 연동 보너스가 발동합니다. 음식을 먹은 뒤의 단발 물약 효과를 편집하는 페이지가 아닙니다.

속성 보너스 예: 최대 체력, 이동 속도. 기본적으로 약 5초마다 평가하며 서버가 조정할 수 있습니다.
물약 효과 예: 체력 재생, 피해 저항. 기본적으로 약 10초마다 갱신됩니다. 기본 주기에서는 효과 시간을 10초보다 길게 해야 끊기지 않습니다.
연동 보너스 여러 그룹의 구간 조건을 같은 설정에 쓰고 모두 만족하면 활성화됩니다.

연동 조건은 AND 관계입니다. 어느 한 그룹이라도 구간을 벗어나면 성립하지 않습니다.
단계를 벗어난 뒤: 보너스는 유지되지 않고 갱신 주기에 업데이트됩니다. 속성 수정자는 회수되고 물약 효과는 남은 시간에 따라 종료되므로 효과 시간은 갱신 주기에 맞춰야 합니다.

독립 효과와 속성 보너스 페이지

단계 페이지의 녹색 '효과' 진입점에서 들어갑니다. 활성화된 그룹만 표시됩니다. 그룹 막대에서 단계를 클릭하면 시작/끝을 채울 수 있고 수동 입력 후 '사용자 지정'을 눌러 범위를 전송합니다. Shift 클릭으로 단계 선택을 추가/해제할 수 있습니다. 여러 그룹을 선택하면 선택한 각 구간 조합을 nutrition_bonuses에 개별 저장합니다. 이 조건을 단일 그룹 단계표로 해석하지 마세요.

화면 근거: EffectManageScreen.buildGroupRangeControls/buildBottomButtons/saveEffectRows와 현재 zh_cn 라벨. 아이템 단발 섭취 효과는 섭취 물약 효과를 참고하세요.

05조건 규칙

일반 영양 계산은 섭취 시 직접 실행됩니다. 조건 규칙은 일반 계산 후 영양 구간에 따라 추가 변화나 명령어를 결정합니다.

조건 규칙은 여러 영양 그룹을 동시에 확인할 수 있고 모두 만족하면 임의 그룹에 가감산, 명령어 실행, 또는 둘 다를 수행합니다. 조건 그룹과 대상 그룹은 달라도 됩니다.

음식 섭취먼저 일반 영양 수치 계산

→
결과 실행영양 변화 / 명령어

조건 규칙은 일반 영양 계산 후 실행됩니다. 같은 음식이 같은 그룹에 일반값과 조건 변화를 모두 설정하면 두 처리가 순서대로 계산됩니다.

조건 규칙 1개 · 예시

발동 조건 육류 0–86 AND 과일 30–100
영양 변화 육류 +20 당분 -5
선택 명령어 실행 알림 표시 획득 배율

자주 쓰는 두 가지 설정

상한 제한

조건: 육류가 0–86. 대상: 육류 +20.

현재 80에서 먹으면 최대 86까지. 현재 90이면 조건이 성립하지 않아 증가하지 않습니다.

감소 보정

조건: 육류가 86–100. 대상: 육류 -30.

현재 95에서 먹으면 86 근처까지 내려가 멈추고 저값 구간으로 계속 들어가지 않습니다.

같은 그룹 중복 계산: 같은 음식이 같은 그룹에 일반 영양값과 조건 변화를 모두 설정하면 두 처리가 순서대로 실행됩니다. 보통 한 가지 표현만 남겨 중복 계산을 피하세요.

06편집기와 변형

아이템을 들고 /hdui를 입력하면 해당 아이템의 설정 진입점이 열립니다.

편집기는 영양, 음식 싫증, 갈증, 허기, 스택, 품질, 보존 기간, 효과, 명령어, 조건, 효과 제거를 통합합니다. 아래 그림은 레이아웃 예시이며 실제 스크린샷이 아닙니다.

아이템 편집기 · 예시아이템을 들고 /hdui

또 다른 진입점: /hdui create의 영양 수치 Tab

/hdui create는 OP4가 필요하고 생성/수정하는 것은 영양 그룹 정의이며 특정 플레이어의 현재 값을 수정하는 것이 아닙니다. 품질과 희귀도는 같은 편집기의 다른 두 Tab에 있습니다. 품질 그림, 희귀도 그림으로 바로 이동할 수 있습니다.

화면 근거: HdCreateScreen.buildGroupForm/buildHeaderButtons/groupErrors. 신규 아이템 등록은 등록 관리자를 참고하세요.

NBT 변형: 같은 이름 아이템의 독립 설정

같은 아이템을 NBT로 여러 변형으로 나누고 각 변형이 독립된 설정을 저장할 수 있습니다. 섭취 시 일치하는 변형의 설정을 사용합니다. 예를 들어 같은 물약의 다른 NBT에 다른 영양을 설정할 수 있습니다.

변형 A 치유 물약
과일 +8
당분 +4
변형 B 신속 물약
단백질 +6
채소 +3
변형 값은 예시입니다. 각 변형은 독립 설정을 저장하고 공통 항목을 자동 상속하지 않습니다.
스택 한도는 아이템 레벨 속성: 같은 아이템의 다른 변형에 서로 다른 스택 수를 설정할 수 없습니다. 갈증 수치 등 아이템 레벨 설정도 마찬가지입니다.

자주 쓰는 진입점

  • /hdui create (OP4): 영양 그룹, 품질, 희귀도 정의 생성/수정. 그룹 ID는 생성 후 자유롭게 변경할 수 없고 독립 아이템도 등록하지 않습니다.
  • /hdui stage (OP4): 단계/명령어/설명 편집을 열고 녹색 '효과'에서 독립 보너스 페이지로 이동합니다.
  • /hdui groups [플레이어] (OP4): 실행자가 자신 또는 지정 플레이어의 수치 관리 화면을 엽니다. 일반 영양 패널이 아니며 그룹 정의도 생성하지 않습니다.
  • /hdui registry (OP4): 등록 관리자를 열어 등록 항목 보기, 새로고침, 삭제를 합니다. 새 아이템 ID는 시작 절차로 활성화됩니다.
  • /hdui tooltip (OP4): 손에 든 아이템의 툴팁 편집 진입점입니다. 자세한 내용은 툴팁 편집을 참고하세요.

영양 그룹 정의는 데이터팩이 담당하고 편집기에서 생성하거나 수정한 내용은 설정 오버레이에 기록됩니다. 구 /hdgroups는 삭제되었습니다.

07관리와 명령어

일반 플레이어는 자신의 패널을 볼 수 있습니다. 다른 플레이어의 값을 수정하거나 영양 그룹을 일시 중지하려면 권한이 필요합니다.

명령어권한 / 용도와 대상
/headiet 또는 /headiet open플레이어 본인, OP 불필요: 영양 패널을 자신에게 보냅니다.
/headiet open <플레이어>OP2: 영양 패널을 지정 플레이어에게 보냅니다. 실행자가 해당 플레이어의 패널을 보는 것이 아닙니다.

08요점 정리

  1. 수치 범위는 0–100. 소수는 유지되고 단계 판정 시 반올림됩니다.
  2. 영양 수치는 허기 소비에 따라 감소율로 줄어듭니다. 포화도는 관여하지 않고 사망해도 사라지지 않습니다.
  3. 단계는 지속 상태를, 조건 규칙은 단일 섭취 계산을 제어합니다. 실제 그룹, 임계값, 효과는 서버 설정을 따릅니다.
