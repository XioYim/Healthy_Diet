09 / SERVER ADMIN

권위 설정, 클라이언트 표시, 시작 시 등록을 먼저 구분하세요.

서버 관리자는 설정 파일, 데이터팩 오버레이, 게임 내 편집기 세 진입점에서 편집할 수 있습니다. 변경 유형에 따라 새로고침 방식이 다릅니다.

server.json데이터팩 오버레이리로드와 동기화
경로 설명: 아래 경로는 게임 또는 서버 인스턴스의 config/healthy_diet/ 기준 상대 경로입니다. 문서는 현재 소스가 지원하는 설정 구조를 설명하며 실제 활성화 여부, 데이터팩 덮어쓰기 순서, 지원 플랫폼은 설치된 파일과 서버를 따릅니다.
필드별로 확인하시나요?새 페이지는 server.json, display.json, 영양 데이터팩, 아이템/블록, 보존 기간/온도, 외형 필드를 파일별로 정리하고 기본값과 업데이트 방법을 제시합니다.

01현재 설정 파일부터 시작

상대 경로담당 내용
server.json서버 게임플레이, 개인정보, 보존 기간 스택 병합 임계값 등 설정 섹션.
display.json클라이언트 표시 설정. 서버 게임플레이 스위치의 유일한 소스가 아닙니다.
colors/color_schemes.json
colors/solid_colors.json		그라데이션 스킴과 단색 팔레트.
fatigue/fatigue_gradient.json
fatigue/fatigue_exempt.json		음식 싫증 툴팁 색상, 단기 쿨다운 회복 카운트 제외 아이템 목록.
shelf_life/schemes/보존 기간 표시 스킴. 온도/계절 관련 설정도 해당 현재 디렉터리에 있습니다.
bottle_fills.json

구경로를 그대로 쓰지 마세요: server_privacy.json, shelf_merge.json 등 구 파일은 server.json의 해당 섹션으로 이동했습니다. 구 items/, tooltips/, blocks/ 설정 디렉터리도 현재 데이터팩 경로가 아닙니다.
소스 근거: ConfigManager 파일 경로 상수와 ServerConfigFile.migrate.

02데이터팩 정의와 설정 오버레이

아이템과 툴팁, 영양 그룹, 단계, 보너스, 품질, 희귀도, 블록 규칙은 데이터팩 정의를 지원합니다. config/healthy_diet/datapack/을 통해 이 모드의 로컬 오버레이를 제공합니다.

경로 구조 예시

config/healthy_diet/datapack/data/<네임스페이스>/healthy_diet/<유형>/<파일>.json

예를 들어 quality_levels/는 품질 정의, blocks/는 우클릭 블록 규칙을 저장합니다. 다른 유형은 게임 내 편집기에 표시되는 실제 소스 경로로 찾으세요.

편집기가 저장한 설정 오버레이와 월드 기존 데이터팩이 함께 로드됩니다. 수정 전에 대상 항목의 소스를 확인하세요. 설정 오버레이는 데이터를 구 config/healthy_diet/items/에 복사한다고 적용되는 것이 아닙니다.

아이템 설정 찾기

먼저 아이템의 네임스페이스와 ID를 확인하고 data/<네임스페이스>/healthy_diet/items/<아이템경로>.json을 찾습니다. 툴팁도 마찬가지로 healthy_diet/tooltips/를 사용합니다. 편집기가 기록한 HD 오버레이와 다른 데이터팩의 같은 항목이 동시에 존재할 수 있습니다. 오버레이를 삭제해도 아래에 데이터팩 정의가 남아 있으면 폴백하며 해당 아이템을 완전히 비활성화한다는 보장은 없습니다.

소스 근거: ConfigManager의 pack 로더, PackJsonLoader, 오버레이 소스 조회.

03/hdreload와 기타 명령어

/hdreload는 OP4가 필요하고 Healthy Diet 자체의 리로드 가능한 설정과 디스크 오버레이만 다시 읽고 온라인 플레이어에게 서버 권위 콘텐츠를 다시 보냅니다. Minecraft의 전체 /reload가 아닙니다. 오버레이 파일을 수동으로 추가·수정·삭제한 뒤 유형별로 리로드 결과를 확인할 수 있습니다.

플레이어와 아이템 관리/headiet로 영양 패널을 엽니다. /hdui로 손에 든 아이템과 편집 진입점을 관리하고 /hdui stage로 영양 단계를 관리합니다.
확인과 도움말/hdhelp로 플레이어가 명령어 구문을 확인합니다. /hdtemperature는 현재 위치 온도 내역을 보고하고 /hdtrust는 보호 허용 목록을 관리합니다.

관리 명령어가 모든 플레이어에게 개방된 것은 아니며 권한은 각 명령어 등록 조건을 따릅니다. /hdreload는 관리 권한 레벨 4가 필요합니다. /hdconfig는 클라이언트 로컬 명령어이며 실행 자체에 OP4가 필요합니다. 전용 서버 콘솔 명령어가 아닙니다. 비 OP 플레이어도 다른 화면에서 로컬 외형 설정에 들어갈 수 있습니다. 자세한 내용은 설정 화면 도해를 참고하세요.

설정 변경 후 판단 방법

HD 오버레이를 저장하거나 업데이트한 뒤 /hdreload를 실행하고 명령어 피드백과 블록 '로드됨/변형/폐기' 카운트를 확인한 다음 실제 아이템이나 블록으로 검증합니다. 편집기의 일부 저장 동작은 이미 이 모드의 리로드를 자동 호출합니다. 월드 데이터팩이나 다른 모드 리소스를 변경한 경우 각자의 로드 절차를 따라야 하며 /hdreload를 바닐라 /reload로 간주할 수 없습니다.

소스 근거: HDReloadCommand, HDUICommand, HDClientCommands.

04리로드만으로 반영되지 않는 변경

  • 1새 아이템 ID 등록: 등록 정의는 시작 단계에서 활성화됩니다. 리로드는 시작 대기 계획만 다시 계산하며 새로운 실행 시 ID를 임시로 만들 수 없습니다.
  • 2클라이언트 로컬 파일: 예를 들어 display.json, 로컬 그라데이션, 안개 효과 등은 서버의 /hdreload로 강제 원격 재읽기되지 않습니다.
  • 3스택 한도: 아이템 레벨 속성 변경은 재시작이 필요합니다. NBT 변형마다 서로 다른 스택 한도를 가질 수 없습니다.

멀티 서버에서 품질 등록 아이템을 추가하면 클라이언트는 로그인 전에 일치하는 등록 목록과 관련 리소스를 받고 등록 절차에 따라 재시작해야 합니다. '서버 측 리로드 완료'를 '클라이언트가 새 ID를 이미 보유'로 간주하지 마세요.

업데이트 방법을 판단하는 3단계: 서버에서 리로드 가능한 아이템, 툴팁, 영양 데이터 변경 → /hdreload의 로드 피드백과 배포 확인. 플레이어 로컬 표시/안개 거리 변경 → 해당 클라이언트가 로컬 절차로 다시 읽도록 함. quality_registry/의 등록 ID 추가·삭제, 스택 한도 변경 → 시작 시 등록 또는 아이템 속성 요구 사항에 따라 재시작. 앞 유형이 배포되었다고 뒤 두 유형도 완료된 것은 아닙니다.
소스 근거: QualityRegistryEntry, ItemConfig.stackSize, HDReloadCommand, ConfigManager.
구체적인 기능을 확인하시나요?챕터 맵으로 돌아가 영양, 보존 기간, 품질 장에서 플레이어 대상 실제 규칙을 확인하세요.

05자주 쓰는 명령어와 권한

명령어권한용도
/hdhelp모두게임 내 전체 명령어 색인. 호버로 설명, 클릭으로 입력창 삽입.
/headiet모두자신의 영양 패널 열기. 다른 사람 보기는 OP2, 영양 수치 수정은 OP4.
/hdinfo [아이템]모두주 손 일치 변형 또는 지정 아이템의 기본 스택을 확인하고 로컬 음식 쿼리 뷰어를 엽니다.
/hdtemperature모두현재 온도 소스, 블록 기여, 사용 가능한 연동을 진단.
/hdtrust모두자신의 아이템/컨테이너 신뢰 플레이어 목록 관리.
/hduiOP4주 손 아이템 설정 센터 열기.
/hdui createOP4영양 그룹, 품질 레벨, 희귀도 정의 관리.
/hdui stageOP4단계, 진입 명령어, 조건 보너스 관리.
/hdui groups [플레이어]OP4플레이어 영양 수치와 그룹 상태 관리.
/hdui tooltipOP4아이템 툴팁 편집 진입점 열기. 변형이 있으면 해당 줄을 먼저 선택.
/hdui registryOP4시작 시 등록되는 품질 아이템 관리. 손에 든 아이템 불필요.
/hdset rarityOP2아이템에 희귀도 지정 또는 해제. 자세한 인자는 /hdhelp 참고.
/hdcloneitemOP4보조 손의 설정된 항목을 주 손에 부분적으로 덮어쓰기. 초기화 후 완전 교체가 아닙니다.
/hdreloadOP4이 모드 설정을 리로드하고 온라인 플레이어에게 다시 전송. 바닐라 전체 /reload를 트리거하지 않습니다.
/hdconfig클라이언트 로컬 OP4클라이언트 설정 화면 열기. 전용 서버 콘솔에는 등록되지 않습니다.
/titlepro 등OP2TitlePro 타이틀, 템플릿, 표, 지우기, 화면 색상 오버레이.

/headiet add, subtract, set의 값 변경은 OP4가 필요합니다. /headiet clearaversion으로 지정 아이템의 거부감 기록을 해제하려면 OP2가 필요합니다. /cleartoast로 자신의 업적 토스트를 지우는 데는 권한이 필요 없지만 다른 플레이어를 지정하면 OP2가 필요합니다. 구체적인 인자와 대상 선택은 게임 내 /hdhelp를 사용하고 과거 문서의 구 권한표를 그대로 쓰지 마세요.

소스 근거: 각 명령어 등록 클래스의 권한 조건. 실제는 게임 내 /hdhelp와 설치된 파일을 따릅니다.

06선택 연동과 재시작

선택 모드용도
Jade지원되는 드롭 음식에 보존 기간 정보 표시.
Legendary Survival Overhaul환경 온도, 체감 온도 등 사용 가능한 데이터 소스 제공.
Ecliptic Seasons계절, 기후, 관련 온도/보존 연동 제공.
Refurbished Furniture냉장고/냉동고 보존 연동. NeoForge는 framework도 필요합니다.

이는 기능별 선택 연동이며 기본 플레이의 전제가 아닙니다. 대상 게임 버전에서 서드파티 모드 자체의 사용 가능 여부를 확인하세요.

재시작이 필요한 경우: 시작 시 등록되는 품질 아이템은 양쪽에 일치하는 정의가 있고 시작 시 적용되어야 합니다. 시작 시 콘텐츠 변경은 로그인 후 동기화나 /hdreload만으로 반영되지 않습니다. 클라이언트 로컬 표시 파일의 업데이트 방식도 서버 게임플레이 설정과 다릅니다.
소스 근거: QualityRegistryEntry, ConfigManager, 각 연동 모듈의 준비 판정.
