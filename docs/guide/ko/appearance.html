같은 색상을 서로 다른 정보 위치에 사용할 수 있습니다.

그라데이션 스킴은 색상 소스를 담당하고 동적 스타일은 변화 방식을 담당합니다. 품질, 희귀도, 아이템 이름, 음식 싫증 줄, 보존 기간 상태 줄에는 각각 독립된 설정 경계가 있습니다.

그라데이션 스킴동적 텍스트단색 팔레트
색상 경계: 색상 견본은 웹 페이지 효과만 보여 주며 게임 렌더링을 재현하지 않습니다. 색상 파일과 스킴 수는 실제 설치 파일에 따라 달라지므로 예시 색상을 고정 내장 스킴 목록으로 취급하지 마세요.

이 페이지 목차

  1. 스킴과 단색
  2. 동적 텍스트
  3. 적용 위치
  4. 설정 소속

01색상 스킴과 단색 팔레트

그라데이션 스킴은 colors/color_schemes.json에서 ID로 참조합니다. 단색 팔레트는 colors/solid_colors.json에서 선택 가능한 색상을 정의합니다.

예를 들어 영양 그룹 색상은 그라데이션 스킴을 참조할 수 있습니다. 품질과 툴팁 줄도 스킴을 설정하거나 단색을 직접 사용할 수 있습니다. 색상 표가 제공하는 것은 색상 소스이며 어떤 툴팁 줄을 표시할지 결정하지 않습니다.

색상 견본 예시A → B
예시 색상은 현재 내장 색상의 한 스킴에서 가져왔습니다. 웹 색상 막대는 게임 스크린샷이 아니며 각 영양 그룹의 실제 색상을 나타내지도 않습니다.
소스 근거: ConfigManager의 색상 파일 경로, 기본 스킴, RarityConfig.scheme.

02정적 그라데이션과 동적 스타일

정적텍스트는 문자별로 그라데이션 색상을 할당받고 시간에 따라 변하지 않습니다. 동적 효과가 필요할 때만 해당 스위치를 켭니다.
동적현재 gradient, breathing, wave, pulse 등의 스타일을 지원합니다. 속도, 단계 수, 일부 고유 매개변수를 개별 설정합니다.

물결과 펄스에는 각각의 단계 폭 또는 지연이 있습니다. 색상 순서 반전과 애니메이션 방향 반전도 독립된 두 설정입니다. 툴팁 줄은 여러 텍스트 세그먼트로 구성할 수 있고 각 세그먼트가 고유한 색상과 애니메이션 매개변수를 가집니다.

매개변수 조합

dynamic=false일 때는 문자별 정적 그라데이션을 표시합니다. 동적을 켜면 nameStyle로 애니메이션을 선택하고 speed로 반복 주기(밀리초), steps로 색상 표 샘플링 정밀도를 제어합니다. waveStep은 물결에만, pulseDelay는 펄스의 문자별 전파에만 영향을 줍니다. 세그먼트 텍스트를 사용하면 각 세그먼트가 독립된 색상과 애니메이션을 가지며 최상위 텍스트와 그라데이션 매개변수는 세그먼트 설정을 덮어쓰지 않습니다.

소스 근거: TooltipLineConfig의 dynamic, nameStyle, segments, colorReverse, dynamicReverse.

03색상을 적용하는 위치

  • 1아이템 이름과 툴팁 추가 줄: 텍스트, 그라데이션, 세그먼트, 동적 스타일, 표시 조건을 설정할 수 있습니다. 이름 줄과 추가 줄은 제한이 다릅니다.
  • 2품질과 희귀도: 품질에는 오버레이, 세그먼트 품질 텍스트를 설정할 수 있습니다. 희귀도는 희귀도 표시와 관련 아이템 이름 색상에 영향을 줍니다.
  • 3음식 싫증 정보: fatigue/fatigue_gradient.json으로 싫증 관련 툴팁 색상을 관리합니다.
  • 4보존 기간 상태: shelf_life/schemes/의 보존 기간 표시 스킴을 사용하며 공통 그라데이션 팔레트와 구분됩니다.

색상을 바꾸기 전에 대상 줄의 소스를 확인하세요. 영양 그룹 색상, 아이템 이름, 직접 쓴 줄은 하나의 '전역 텍스트 색상' 스위치를 공유하지 않습니다. 품질 텍스트는 품질 정의에서 참조되고 희귀도는 아이템과 NBT 변형별로 덮어쓸 수 있습니다. 공통 그라데이션 스킴을 바꾸면 이를 참조하는 모든 위치에 영향을 줍니다. 한 종류의 툴팁만 바꾸려면 해당 종류의 바인딩 또는 개별 스킴을 편집하세요.

아이템 이름 색상 복제: /hdset tooltip <소스아이템ID> hand|<대상아이템ID> (OP2)는 소스의 아이템 레벨 공통 항목 첫 줄 색상 스킴과 동적 필드를 주 손 대상 또는 명시적 아이템 ID로 복사합니다. 첫 줄 텍스트, 별표, 다른 줄, NBT 변형은 복사하지 않습니다. 소스 또는 대상 첫 줄이 세그먼트 텍스트이면 거부되며 세그먼트 색상을 직접 복제할 수 없습니다. 세그먼트별로 편집하려면 툴팁 편집 진입점에서 작업하세요.
소스 근거: HDSetCommand.buildTooltipNode/doTooltipCopy, QualityLevelConfig, TooltipLineConfig.

04서버 측 규칙과 클라이언트 표시

서버 관리자는 규칙성 콘텐츠를 유지하고 온라인 플레이어에게 동기화할 수 있습니다. 예를 들어 음식 툴팁 레이아웃, 품질 정의, 보존 기간 표시 스킴입니다. 클라이언트 로컬 표시 설정과 일부 로컬 색상 파일은 서버에서 /hdreload를 실행해도 자동으로 원격 재읽기되지 않습니다.

따라서 외형을 수정하기 전에 설정 파일이 서버에서 배포되는지, 각 클라이언트가 직접 설치·리로드·월드 재입장해야 하는지 구분하세요. 등록 품질 아이템의 사용자 지정 텍스처는 클라이언트에 해당 리소스도 있어야 합니다.

'서버 관리자가 바꿨는데 나는 그대로' 조사

대상이 아이템/품질 등 서버 정의에 있는지, 플레이어 클라이언트 로컬 색상에만 있는지 확인하고 클라이언트에 텍스처나 글꼴 리소스가 있는지도 확인합니다. /hdreload는 동기화 가능한 서버 측 규칙을 다시 읽고 배포하지만 플레이어의 로컬 파일을 바꾸지 않습니다. 웹 색상 견본도 서버 데이터를 자동으로 따라가지 않습니다.

경로 마이그레이션: 구버전 rarity_and_colors/와 shelf_env/ 디렉터리는 현재 편집 경로가 아닙니다. 실제 설치 디렉터리의 colors/, fatigue/, shelf_life/를 확인하세요.
