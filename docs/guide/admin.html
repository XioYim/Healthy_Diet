02数据包定义与配置覆盖层

物品与 Tooltip、营养组、阶段、加成、品质、品级、方块规则均支持数据包定义；通过 config/healthy_diet/datapack/ 提供本模组的本地覆盖层。

路径结构示意

config/healthy_diet/datapack/data/<命名空间>/healthy_diet/<类型>/<文件>.json

例如 quality_levels/ 存品质定义、blocks/ 存右键方块规则；其他类型要按游戏内编辑器显示的实际来源路径定位。

编辑器保存的配置覆盖层与世界已有的数据包会共同参与加载。修改前应先确认目标条目的来源；配置覆盖层不是把数据复制进旧的 config/healthy_diet/items/ 就能生效。

定位一个物品配置

先确认物品的命名空间和 ID，再找 data/<命名空间>/healthy_diet/items/<物品路径>.json；Tooltip 同理使用 healthy_diet/tooltips/。编辑器写出的 HD 覆盖层与其他数据包的同一条目可能同时存在：删掉覆盖层后，底下仍有数据包定义时会回落，而非保证彻底禁用该物品。

源码依据：ConfigManager 的 pack 加载器、PackJsonLoader 与覆盖层来源查询。

03/hdreload 与其他命令

/hdreload 要求 OP4，只重载 Healthy Diet 自身可重载的配置和磁盘覆盖层，并向在线玩家重新下发服务端权威内容；它不是 Minecraft 的全量 /reload。手工新增、修改或删除覆盖层文件后，可按类型检查重载结果。

玩家与物品管理/headiet 打开营养面板；/hdui 管理手持物品和编辑入口，/hdui stage 管理营养阶段。
查询与帮助/hdhelp 供玩家查命令语法；/hdtemperature 报告当前位置温度分解；/hdtrust 管理保护白名单。

管理命令并非都对所有玩家开放，权限需按各命令注册条件执行；/hdreload 要求管理权限等级 4。/hdconfig 是客户端本地命令，执行命令本身需 OP4，不是专用服务器控制台命令；非 OP 玩家仍可从其他界面进入本地外观配置，详见 配置界面图解。

改完配置怎样判断

保存或更新 HD 覆盖层后执行 /hdreload，看命令反馈及方块「已加载/变体/丢弃」计数，再用实际物品或方块验证。编辑器的某些保存动作已自动调用本模组重载；如果改的是世界数据包或其他模组资源，仍要按其各自的加载流程处理，不能把 /hdreload 当成原版 /reload。

源码依据：HDReloadCommand、HDUICommand、HDClientCommands。

04哪些修改不能只靠重载

  • 1注册新物品 ID：注册定义在启动阶段生效；重载只能重算待启动方案，不能临时创造新的运行期 ID。
  • 2客户端本地文件：例如 display.json、本地渐变色、雾效等，不会由服务器执行 /hdreload 强制远程重读。
  • 3堆叠上限：物品级属性修改需重启；NBT 变体无法各自拥有不同堆叠上限。

多人服务器若新增品质注册物品，客户端应在登录前取得一致的注册清单和相关资源，然后按注册流程重启。不要把“服务端重载完成”当作“客户端已经拥有新 ID”。

三步判断刷新方式：改服务器可重载的物品、Tooltip 或营养数据 → 检查 /hdreload 的加载反馈与下发；改玩家本地显示/雾距 → 让相关客户端按本地流程重新读取；新增或删除 quality_registry/ 中的注册 ID、变更堆叠上限 → 按启动期注册或物品属性的要求重启。前一类已下发，不等于后两类也完成。
源码依据：QualityRegistryEntry、ItemConfig.stackSize、HDReloadCommand、ConfigManager。

05常用命令与权限

指令权限用途
/hdhelp所有人游戏内完整命令索引，悬停看说明；点击只填入输入框。
/headiet所有人打开自己的营养面板；查看他人需 OP2，修改营养值需 OP4。
/hdinfo [物品]所有人查询主手命中变体或指定物品的默认堆叠，打开本机食物查询器。
/hdtemperature所有人诊断当前温度来源、方块贡献及可用联动。
/hdtrust所有人管理自己物品／容器的受信任玩家名单。
/hduiOP4打开主手物品的配置中心。
/hdui createOP4管理营养组、品质等级与品级定义。
/hdui stageOP4管理阶段、进入指令和条件加成。
/hdui groups [玩家]OP4管理玩家营养值与组状态。
/hdui tooltipOP4打开物品 Tooltip 编辑入口；存在变体时先选中对应行。
/hdui registryOP4管理启动期注册的品质物品；无需手持物品。
/hdset rarityOP2给物品指定或清除品级；具体参数查看 /hdhelp。
/hdcloneitemOP4将副手物品已经配置的项目局部覆盖主手物品，而不是清空后完整替换。
/hdreloadOP4重载本模组配置并重推在线玩家；不触发原版完整 /reload。
/hdconfig客户端本地 OP4打开客户端配置屏；专用服务器控制台不注册这条命令。
/titlepro 等OP2TitlePro 标题、模板、表格、清除和屏幕颜色覆盖层。

/headiet add、subtract、set 修改值需要 OP4；/headiet clearaversion 解除指定物品的厌食记录需要 OP2。/cleartoast 清自己的成就弹窗无须权限，带其他玩家时需 OP2。具体参数和目标选择请使用游戏内 /hdhelp，不要照抄历史文档里的旧权限表。

源码依据：各命令注册类的权限条件；实际以游戏内 /hdhelp 和所安装文件为准。

06可选联动与重启

可选模组用途
Jade对支持的掉落食物显示保质期信息。
Legendary Survival Overhaul可提供环境温度、体感等可用数据来源。
Ecliptic Seasons可提供季节、气候与相关温度／保鲜联动。
Refurbished Furniture可接入冰箱／冷冻柜保鲜；NeoForge 还需其 framework。

这些是按功能使用的可选联动，不是基础游玩的前置；请依据目标游戏版本确认第三方模组本身的可用性。

什么时候需要重启：启动期注册的品质物品需要两端拥有匹配定义并在启动时应用；修改启动期内容不能只靠登录后同步或 /hdreload。客户端本地显示文件的刷新方式也不同于服务端玩法配置。
源码依据：QualityRegistryEntry、ConfigManager 与各联动模块的就绪判定。
